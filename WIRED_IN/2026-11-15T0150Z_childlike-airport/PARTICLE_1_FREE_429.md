# particle-ai/particle-1:free 429

Not a bad model id. Not a local auth failure.

The failing call was `POST https://openrouter.ai/api/v1/chat/completions`. OpenRouter returned HTTP 429 with `isRetryable: true`, `retry-after: 1`, `x-openrouter-error-origin: provider`.

Response body, trimmed:

- `code`: 429
- `provider_name`: Particle AI
- `provider_error_code`: `fleet_capacity_exhausted`
- `limit_source`: `upstream_provider_shared_pool`
- `is_byok`: false
- raw text: `particle-ai/particle-1:free is temporarily rate-limited upstream`

That is the shared free pool in front of Particle, empty at that second. Our slug matches the provider list. A BYOK Particle key is not attached on that route, so OpenRouter cannot fall through to a private quota. Retrying immediately does not help while the fleet is exhausted; the header says 1 second and the pool can stay empty longer than that.

## Where it sits in Kilo

`~/.config/kilo/kilo.jsonc` (not this repo):

- `openrouter` model `particle-ai/particle-1:free` — this is the route that 429'd. Display name now says shared-pool 429, do not pin.
- `aihubmix` model `particle-1-free` — different host, uses the AIHubMix key, marked as the keyed fallback. It was not the call that failed.
- Paid ids `particle-ai/particle-1` and `particle/particle-1` appear only in a discovery include list. They are not the free slug.

No repo file references `particle-ai/particle-1`. Nothing in this worktree was routing through it. The picks in this folder were not generated by that model.

## What to do when it 429s

Do not pin `particle-ai/particle-1:free` as the selected model. Use the AIHubMix `particle-1-free` entry, or any other free model already marked favorite (`openrouter/free`, nemotron, ling). Adding a Particle key at https://openrouter.ai/workspaces/default/byok is the only way to get off the shared pool. Do not commit that key.
