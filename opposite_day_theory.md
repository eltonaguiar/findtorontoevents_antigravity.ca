# Opposite Day – Theory & Methodology

## 1. Motivation
The **Coinglass Long‑Short Ratio** (LSR) shows the net positioning of large
traders (whales).  Empirically we observed that when the LSR for a symbol
exceeds **1.65 (green)** the market tends to reverse shortly after – a classic
*contrarian* signal.

To test whether the opposite side of a model‑generated signal carries any
edge we created a **sandbox** called **"Opposite Day"**.  The sandbox:

* Takes every active pick produced by the primary `crypto_signal_engine`.
* Flips the direction (LONG → SHORT, SHORT → LONG).
* Uses the same risk parameters (ATR‑based TP/SL, 1 % equity risk) so
  performance can be compared on a like‑for‑like basis.
* Tracks win‑rate, profit factor and other classic metrics.

The sandbox runs daily, stores its own pick history and posts a concise
summary to the Discord "sandbox" channel.

## 3. Methodology
### 3.1. Signal Inversion
For each active pick:
1. **Flip direction** – `LONG` → `SHORT`, `SHORT` → `LONG`.
2. **Re‑compute TP/SL** using the same ATR multiplier constants defined
   in `crypto_signal_engine/config.py` (`TP_ATR_MULT`, `SL_ATR_MULT`).
3. Keep the original entry price (the price at which the primary signal
   opened) – this mimics a *pure opposite* trade.
4. Store the mirrored pick with a `source = "opposite_day"` flag.

### 3.2. Risk Management
* **Position size** – 1 % of equity risk (same as the primary engine).
* **Stop‑loss** – ATR × `SL_ATR_MULT` on the opposite side.
* **Take‑profit** – ATR × `TP_ATR_MULT` on the opposite side.

### 3.3. Performance Tracking
Every run:
* Pull the latest price for each sandbox pick.
* Close the pick if TP or SL is hit, record `WIN` or `LOSS`.
* Update a rolling window of the most recent **500** closed picks.
* Compute:
  * **Win‑rate** = wins / (wins + losses) × 100 %
  * **Profit Factor** = Σ(win PnL) / Σ(|loss PnL|)
  * Simple **Sharpe** (optional) = mean PnL / std PnL.
* Persist the statistics to `sandbox/opposite_day_stats.json`.

### 3.4. Correlation with Whale LSR
The sandbox also records the **Coinglass LSR** at the moment a pick is
created.  In the final analysis we can filter picks where `LSR > 1.65`
(green) and compare the win‑rate of the *original* versus the *opposite*
side.  This yields a direct test of the hypothesis:

> *When whales are heavily net‑long (>1.65), the opposite direction
> tends to be profitable.*

## 4. Implementation Overview
* `coinglass_integration.py` – fetches and caches the LSR data.
* `opposite_day_strategy.py` – core sandbox logic (generation, P&L,
  stats).
* `sandbox/` – stores `opposite_day_picks.json`, `opposite_day_closed.json`
  and `opposite_day_stats.json`.
* `discord_status.py` can be extended to post the sandbox stats to the
  Discord "sandbox" channel (simply add the JSON file as an attachment or
  embed the key numbers).

## 5. How to Run
```bash
# 1️⃣ Install dependencies (requests is already in the base env)
pip install -r crypto_signal_engine/requirements.txt

# 2️⃣ Run the main signal engine (scan mode) – this populates active picks
python -m crypto_signal_engine.engine --mode scan

# 3️⃣ Run the Opposite Day sandbox
python opposite_day_strategy.py --run
```
The script can be scheduled (cron) to run after each scan, e.g. every
30 minutes.
