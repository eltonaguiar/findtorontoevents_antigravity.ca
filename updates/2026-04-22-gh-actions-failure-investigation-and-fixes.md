# GitHub Actions Failure Investigation & Fixes — 2026-04-22

## Summary

Investigated all GitHub Actions workflows with failures, cancellations, or startup errors. Found 4 distinct root causes and applied fixes for each.

## Issue 1: CI Tests — 6/7 consecutive failures (0 successes)

**Root Cause:** Test suite `tests/test_phase1_active_gates.py` was testing the OLD confidence < 0.80 gate and 4-hour TOD window (08-11), but production code (`audit_trail/quality_gates.py`) had been updated:
- The confidence < 0.80 gate was **fully reverted** (PR #323) — confidence proved anti-predictive (low conf picks WR 42.8% vs high conf 26.2%)
- Replaced with a **dead-zone gate** targeting only the worst band [0.65, 0.75)
- TOD gate expanded from 4 hours (08-11) to 10 hours (08-11 + 16-21) per PR #291
- Both gates now default to **shadow mode** (tags, doesn't reject) instead of active rejection

**Previous band-aid:** PR #325 `@unittest.skip`'d all 20 tests — CI green but 20 skipped tests, zero actual coverage.

**Fix:**
- Rewrote `Phase1ConfidenceGateTests` → `Phase1DeadZoneGateTests` matching the dead-zone gate semantics
- Updated all TOD tests to explicitly set `PHASE1_TOD_GATE_ENABLED=1` and test both windows (morning 08-11 + afternoon 16-21)
- Added `PHASE1_CONF_DEADZONE_ENABLED=0` to `conftest.py` so non-Phase1 tests don't hit the dead-zone
- Added 10 new tests: afternoon TOD window, boundary tests, shadow mode for both gates, dead-zone override, combined gate interactions
- Removed all `@unittest.skip` decorators — tests now actually execute and verify production behavior

## Issue 2: Alpha Engine Dynamic Runner — 85% failure/cancellation rate

**Root Cause:** The "Commit results" step exits with code 1 when all 10 git push attempts fail. Push failures are common because multiple workflows (audit-dashboard, alpha-engine, meta-strategy, etc.) compete for push access to main. 26 failures + 19 cancellations in the last 50 runs = 85% waste.

**Fix:** Made push failure non-fatal (`exit 0` instead of `exit 1`), added `::warning::` annotation for visibility. Added comment explaining this is safe ONLY because each cycle re-generates data from scratch (shallow clone means unpushed commits are lost anyway).

## Issue 3: Meta-Strategy Permutation Engine — repeated push failures

**Root Cause:** The workflow used `git pull --rebase` + `git stash` pattern which frequently conflicts with generated data files (combo_metrics.json, swarm_weights.json). Only 3 retry attempts with no backoff.

**Fix:** Switched to merge-based push pattern (matching the battle-tested audit-dashboard approach):
- `git pull --no-rebase -X ours` instead of `git pull --rebase`
- Added `git fetch --unshallow` for common ancestor (fetch-depth:1 checkout)
- Increased retries from 3 to 5 with exponential backoff (5s, 10s, 20s, 40s, 80s)
- Made push failure non-fatal with `::warning::` annotation

## Issue 4: Chronically cancelled workflows

**Dashboard Pick Trader** (all runs cancelled): This workflow triggers on push to main but depends on data generated by other workflows. When those workflows hold the push lock, Dashboard Pick Trader gets cancelled by concurrency groups. Not a bug — expected behavior when the generating workflow hasn't finished yet.

**No code changes needed** — this is a scheduling artifact, not a code issue.
