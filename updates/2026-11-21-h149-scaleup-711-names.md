# H-149: scaling the backtest from 47 to 711 names (verdict REJECTED)

**Date:** 2026-11-21
**Files:** `tools/h149_midcap_gross_profitability.py`,
`reports/h149_midcap_gross_profitability_2026-11-21.{md,json}`,
`reports/hypothesis_registry.json`
**Status:** data gap closed; hypothesis REJECTED

## What was wrong

The first H-149 run sampled only 150 SEC CIKs (`--sample-n` default), of which
49 cleared the annual-10-K GrossProfit+Assets filter and 47 had prices. That
produced 556 records over 93 usable rebalances — **6.1 records per 14-day window
against a harness floor of 80** — so `edge_stability_harness` returned `None` for
every window and the verdict was UNTESTED. That was a density artefact, not a
finding.

## What changed

1. **`--sample-n` default 150 → 1900**, documented with the yield arithmetic
   (~33% of random filers clear the fundamentals filter, so 1900 lands near 600
   usable names).
2. **Chunked price downloads** (`_download_closes`): one `yf.download` call for
   hundreds of tickers is throttled or silently truncated by Yahoo, losing every
   name at once. Now 80-ticker chunks with a pause and up to 3 retries, so a bad
   chunk degrades to fewer tickers instead of no price data.
3. **`data.fundamentals_yield_pct`** recorded in the payload so the funnel is
   auditable instead of inferred.

`1900` turned out to be the wrong calibration for the *floor*: it yielded 517
names and 7,414 records (82.5/rebalance), which cleared 80/window in only **3**
windows — enough to score, not enough for `MIN_STABLE_WINDOWS=3` with a
consistent sign. The tool's own `density_gap` said 1.3× more names, so the
production run used **`--sample-n 2600`**.

## Result

| quantity | 47 names | 711 names |
|---|---|---|
| sampled CIKs | 150 | 2,600 |
| usable fundamentals | 49 | 759 (29.2%) |
| with prices | 47 | **711** |
| records | 556 | **10,230** |
| records/rebalance | 6.1 | **86.7** |
| windows ≥80 | 0 | **71** |
| windows scored | 0 | **66** |
| strong windows | 0 | 15 (4+/11−) |
| verdict | UNTESTED | **REJECTED** |

Net edge +0.96% (40 bp stress +0.76%), cost survival 0.83 (0.66 stressed), sign
mixed, per-window eff spanning −0.568…+0.492 with no persistence.

**The +17.78% long/short spread is not a result.** The bottom "decile" holds 49
observations where a tenth of 10,230 records is ~1,023: the GP/A distribution is
left-skewed, so the left tail is a handful of deeply loss-making firms, not a
tradable bucket. Shorting 49 distressed micro-cap observations is not
implementable, and their −15.7% is consistent with distress/delisting.

## Verification

- `--self-check` → `EFF_MIN=0.30 MIN_WINDOW_N=80 MIN_STABLE_WINDOWS=3
  unmodified=True` (thresholds untouched; the tool refuses to emit a verdict
  against a modified gate).
- Deterministic sample (`Random(149).shuffle(pool)[:2600]`), seeded bootstrap,
  cached SEC facts → the run is reproducible.
- Both artifacts parse as JSON; the tool wrote them directly.
- Funnel numbers in the report are taken from the artifact, not retyped.

## Limitations

- Survivorship: random sample of **currently registered** filers.
- Financials/REITs included; GP/A is not meaningful for them.
- The four declared spec deviations stand, so the **literal** pre-registered spec
  remains untested — this rejects the annual-10-K / 40-day variant only.
- Cost is the declared 20 bp fallback, not the repo's measured class slippage.
- `fundamentals_yield_pct` is computed after the price filter (27.3% vs a true
  29.2%), a labelling imprecision left as-is rather than silently redefined.
