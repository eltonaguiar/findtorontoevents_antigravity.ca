## Why the Python change was not merged

Raising the DSR trial count is *more* statistically conservative — deflating over
more trials penalises the best observed cell harder. The PR's own comment argues
the case carefully (695/695 cells rebuilt by `tools/strategy_crosswalk.py`, with
the finer 696-strategy grain rejected as a diagnostic only because it would
exceed the tested search space).

But it **flips live verdicts**. Per `CLAUDE.md`, sizing decisions and verdict
flips need explicit owner sign-off, and the PR predates main's
`_population_invariant()` (`alpha_engine/money_ready_verdict.py:1642`, used at
`:1947`) — its branch version does not contain that function, so merging it
naively would delete a guard that main added later.

That is an owner-level statistical decision, not an autonomous merge.
