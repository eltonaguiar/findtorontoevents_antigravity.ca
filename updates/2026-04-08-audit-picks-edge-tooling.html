Audit picks edge — observability & tooling shipped

April 8, 2026 · /audit/ · Updates index

Reference snapshot in the merged report: dashboard generated_at 2026-04-06T20:11:17Z (re-run analyzers on a fresh dashboard_data.json for current numbers).

What exactly changed

  • Live JSON snapshot — tools/fetch_audit_dashboard_snapshot.py downloads the same dashboard_data.json the browser loads from production so offline analysis matches the live audit page.
  • Active book analyzer — tools/analyze_audit_active_book.py: counts by asset_class, aggregate unrealized PnL (excluding flagged rows), score vs unrealized correlations, Verified Alpha tagging share, strategy joins to recent_closed with 30d/90d closed counts, and payload_systems_unrealized echo from systems[].
  • Existing analyzers wired to the same file — tools/analyze_audit_scores_vs_pnl.py and tools/analyze_asset_class_edge_flaws.py are part of the documented run chain (quintiles, rank IC by slice, flaw flags).
  • Artifacts — machine-readable outputs under tools/data/ (e.g. audit_active_book_analysis.json, score_pnl_analysis.json, asset_class_edge_flaws_analysis.json); snapshots directory gitignored with .gitkeep.
  • Documentation — docs/AUDIT_PICKS_EDGE_ANALYSIS_2026-04-06.md (single merged narrative), docs/AUDIT_PLAN_CROSS_ASSET_REVIEW_2026-04-06.md, docs/ASSET_CLASS_EDGE_SCORING_FLAWS_2026-04-07.md, TRACE_LOG.MD pipeline alignment, docs/REDIS_BUS_CHANGELOG.md rows for fleet sync.
  • Bus posts — tools/bus_post_trace_log.py aligned with trace doc; tools/bus_post_audit_picks_edge.py publishes AUDIT_PICKS_EDGE_ANALYSIS (see changelog).
  • Exports caveat — CSV/SQL dumps at fixed paths can disagree with the live dashboard on the same symbol if timestamps differ; the JSON snapshot is the reconciliation source of truth for audit alignment.

Benefits by asset class

These are observability and governance benefits: faster, repeatable answers from one JSON source. They do not by themselves change execution or fills.

Asset class What you can see now Why it matters
CRYPTO Active-book concentration, VA share, closed-history mean PnL positive at scale in the reference run; smart_score shows stronger rank IC on crypto closed trades than open-book noise. Separates “scoring ranks closes” from “open MTM is noisy”; supports crypto-first promotion and calibration work without guessing from the UI.
EQUITY Many actives vs low VA tag rate; closed bucket negative mean/median in reference data; score can rank while the traded pool bleeds. Makes the toxic universe / gate problem visible in numbers, not only headline cards; equity work shifts toward allowlists and quality filters, not score tweaks alone.
FOREX Small active n; weak headline discrimination in reviews; closed stats negative mean in the reference slice. Honest labeling as experimental: tooling prevents over-weighting forex until gates and data depth improve.
COMMODITY / ETF / FUTURES Closed counts surfaced with small-n warnings in the analyzers and docs. Avoids overfitting narratives from thin buckets; keeps reporting proportional to sample size.
SPORTS Appears on the same active-book and trace surfaces as other classes (sparse in the reference snapshot). Single pipeline for cross-asset audit; sports volume grows without a separate ad-hoc reporting path.
