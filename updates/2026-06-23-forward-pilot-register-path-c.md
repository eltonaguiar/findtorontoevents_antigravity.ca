| Strategy | n | WR (win_rate_pct/100) | PF | ssp% |
|----------|---|-----------------------|---|------|
| **battleground_luxalgo** (CRYPTO) | 14 | 71.4% | 2.83 | (intrinsic) |

This candidate lives in pf_registry.json but has **no `.py` source file under `alpha_engine/`** — it's emitted externally (consensus / QuanEngine / contributor data). To accumulate n≥30 resolved class-mates (or ≥5 fwd resolved for the HC tier), it must be wired into the forward-test harness WITHOUT promoting it to live sizing. That's why Path C was chosen over:

- **(A)** Manual edit of `forward_candidate_scoreboard.json` — cron overwrites it each hour.
- **(B)** Manual edit of `entry_conditions_forward.json` — file is 9 KB, error-prone, non-auditable.
- **(D)** Hard-coding into `alpha_engine/forward_n100_tracker.py` (~240 lines) — accretes tech debt on every external strategy.

Path C: a dedicated, ~245-line script + a separate runtime registry that survives cron overwrites + is diff-friendly + idempotent + atomic-write.

## How the registry feeds the runtime

`alpha_engine/non_crypto_policy.py` checks each incoming pick for `forward_test_only`:

```
Line 131:   if p.get("forward_test_only") in (True, 1, "1", "true", "True"):
Line 200:   if forward_test_only: ... bypass daily cap
```

Picks flagged true go to the SHADOW lane (paper-only, no live equity allocation). They DO still accumulate in `at_signal_outcomes` so forward WR/PF can be measured; they just don't pollute the consensus / scoring layer.

**Next-time PR target**: amend `tools/stamp_entry_conditions.py` (and the equivalent stamping in `forward_n100_tracker.py`) to **read `forward_pilot_registry.json` and stamp the flag at emission time** for matching `(strategy, direction)`. Currently the registry is documented but the ingestion hook is implicit (caller must set the flag). That is fine for an explicit one-off pilot (this PR); for >5 candidate strategies at once, the auto-stamp hook is preferable.

## Risk + mitigation

- **Risk**: forgetting to remove-row from the registry produces a permanent `forward_test_only=true` flag on live consumes if a future ingestion path doesn't honor it. Mitigation: registry is small, hand-audited, listed via `--list`. AGENTS.md mandates "Don't take significant actions beyond the clear scope of the request without confirming" — registering a candidate is reversible via `--remove`.
- **Risk**: script accidentally overwriting a corrupt registry. Mitigation: `_load()` raises `SystemExit("FATAL: registry at {path} is not valid JSON; refusing to overwrite")` on JSON decode error; never silently overwrites.
- **Risk**: `os.replace()` is atomic on POSIX but Windows pre-3.3 had known MoveFileEx quirks. Mitigation: Python 3.11+ repo-wide; modern enough.
