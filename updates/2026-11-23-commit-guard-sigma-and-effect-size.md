# 2026-11-23 — commit guard, an empirically derived σ, and the effect size the gate actually needs

## 1. A pre-commit guard, because a rule that needs remembering is not a control

**Why.** This clone had a real incident today: another agent committed 24 foreign files onto HEAD in
the gap between my `git add` and my `git commit --amend`, so the amend rewrote **their** commit and
folded my note into it. Author identity cannot catch this — every agent here commits as
`github-actions[bot]` — so ownership has to be declared by path and enforced mechanically.

**What was added.**

- `tools/agent_ownership.json` — per-agent `owned_prefixes`, plus an explicit `foreign_prefixes` list
  (the files other agents own that I must never stage: `___HELL_HEALTH_OPENCODE.MD`,
  `docs/audit_review_2026-11-22/`, `data/fundamentals_pit/`, `data/realtime_channel`… `investments/goldmines/`).
- `tools/git_guard_check.py` — the decision logic, three modes: `commit` (staged set must be yours),
  `amend` (**every file in HEAD** must be yours, because amending re-signs its whole content as yours),
  and `head` (refuses when HEAD moved mid-operation — the race detector).
- `.githooks/pre-commit` — detects `--amend` from the reflog action, the live git command line, and
  git's own argument, then delegates. `install.sh` now chmods it.
- `tests/test_git_guard.py` — **11 hermetic tests** in a throwaway repo: amends of foreign HEAD refused,
  own HEAD allowed, foreign staged file refused, unregistered agent warns but never blocks, HEAD-moved
  refused, override honoured but announced, **missing ownership file is an error, not a pass**.

An unregistered agent is never blocked (warn only), so this cannot wedge another agent's workflow; it
only stops *my* commits from carrying their files, and theirs from being rewritten by me.

## 2. σ is now measured, not back-solved

The per-class matrix was missing from this clone, so the last memo had to recover σ from a published
`expected_max_sharpe_daily`. It has been regenerated by re-running the harness over its registered cells
— same parameters, no new cells, no new knobs.

| σ | value | vs back-solved |
|---|---:|---|
| **empirical across 38 cells** | **0.020485** | **0.899×** |
| back-solved | 0.022798 | 1.000× |
| SE of one estimate | 0.020089 | 0.881× |

The back-solved figure was right within 10%, so every conclusion built on it stands. More importantly
**SE/σ = 0.98 ≈ 1**, which is the empirical form of the earlier objection: trials here behave like
independent draws, so **"~25 effective trials" is unsupported by the data**, not merely by argument.

## 3. The effect size the gate needs: +25%, i.e. ~20.4 bp/day

DSR = 0.95 at N=120 requires **SR_daily ≥ 0.0863 → annualised 1.37**, which at the book's 236 bp/day
volatility is **≈20.4 bp/day** against the current 16.3 — **a 25% improvement**, or Sharpe 1.37 instead
of 1.095.

**And nothing in the repo is near it in a way that survives.** Exactly one of 39 cells clears 1.37:
**H-228 funding carry, SR 3.205** — on **219 days**, with a bootstrap **CI-LB of −0.005 bp/day** and a
**DSR of 0.9494**, five ten-thousandths short of the gate. Every cell with a positive lower bound
(H-201 +7.246, H-200:NVDA +8.727) has a Sharpe *below* the bar (1.168, 0.997) and DSRs of 0.156 / 0.044.

So the two requirements — a binding lower bound and a Sharpe above 1.37 — are met by **disjoint sets of
cells**. That is the most precise statement of "not ready" this programme has produced.
