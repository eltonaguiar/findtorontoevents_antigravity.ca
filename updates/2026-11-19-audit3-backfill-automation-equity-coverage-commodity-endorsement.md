# audit3: scheduled backfill, full equity coverage, commodity emitters, and my endorsement

Date: 2026-11-19. Surface: `findtorontoevents.ca/audit3` (generated by `alpha_engine/audit3_*`
and `.github/workflows/audit3-ledger.yml`). DB: `ejaguiar1_stocks` @ `mysql.50webs.com`.

Four requests are answered here. Each section states **what broke**, **what changed
and where**, **how it was verified**, and what is still open.

---

## 1. Bounded price-table backfill is now part of the hourly ledger run

**What broke.** Selection alpha (G8) needs a daily bar at or after each pick's exit
timestamp. Three of the four daily tables had stopped long before the picks did:

| table | last bar before | consequence |
|---|---|---|
| `equity_daily_ohlcv` | 2026-06-18 | 486 of 765 EQUITY picks closed after it |
| `futures_daily_ohlcv` | 2026-06-21 | 51 of 51 COMMODITY picks closed after it |
| `fx_prices` | 2026-02-09 | FOREX effectively unpriced |
| `etf_daily_ohlcv` | 2026-10-30, 36 symbols | tracking too few symbols to matter |

Nothing in the sidecar said *why* a class was `unmeasured`, so the gate silently
reported whole asset classes as unmeasurable. A manual backfill on 2026-11-19 took
coverage from 2,228/3,500 to 3,173/3,500 picks — but that is a one-off, and the
tables drift stale again within days. A prerequisite of a gate cannot be a manual step.

**What changed.** `.github/workflows/audit3-ledger.yml` — new step
`Backfill price tables (bounded, best-effort)`, inserted at **index 3, immediately
before** `Selection alpha (optional — needs the price tables)` (index 4). Verified by
parsing the workflow and asserting the order, not by eye.

Safety properties, each deliberate:

* **Bounded** — `SINCE=$(date -u -d '4 days ago' +%F)`, inside the 5-day
  `TOLERANCE_MS` the gate already uses, so it fetches a few days, never history.
* **Upsert-only** — `INSERT ... ON DUPLICATE KEY UPDATE` on the existing unique keys;
  re-running is idempotent, nothing is deleted, no schema change.
* **`continue-on-error: true`** plus explicit `::warning` annotations — a yfinance
  outage downgrades freshness, it never fails the run or costs us the ledger.
* **Skips cleanly** when `DB_PASS_STOCKS` is absent, matching the alpha step.
* Covers all four tables: `tools/backfill_daily_ohlcv.py --tables equity,etf,futures`
  and the pre-existing `tools/fx_backfill.py --since --apply`.

**Verified.** `yaml.safe_load` parses; step list printed as
`0 Checkout → 1 Fetch live ledger → 2 Fetch canonical view → 3 Backfill → 4 Selection alpha
→ 5 audit2 forward → 6 Build ledger → 7 Denylist assert → 8 Commit → 9 Deploy`;
`--help` confirms the CLI; the same commands were run by hand and wrote rows.

## 2. EQUITY coverage 23/37 → 37/37 (the gap was missing symbols, not stale dates)

**What broke.** `/audit3` priced only 23 of the 37 equity symbols the payload needs.
The earlier backfill only advanced symbols the table *already had*, so a symbol that
had never been ingested could not be fixed by any date-bounded run.

Full missing set, computed from the live payload (not from the truncated 10-item
preview): `BBAI, BNGO, BTBT, CHPT, CLSK, JETS, NIO, NVAX, SNAP, SPCE, XLP, XLV, XLY, XPEV`.

Note `JETS, XLP, XLV, XLY` are ETFs carrying `asset_class=EQUITY` — the same
class-label defect family as the crypto/ETF mislabels fixed earlier, just in the
other direction. They are priced now regardless of label.

**What changed.** `tools/backfill_daily_ohlcv.py` — new `--symbols` flag feeding a
`force` set in `universe()` and threaded through `backfill()`. A passed symbol is
added to the universe even when the table has never seen it; the docstring records
why. Dry-run still touches no network.

**Verified.** `--symbols "BBAI,…,XPEV" --apply` → `universe=251 … written=26764`.
Re-running the real gate: **`EQUITY priced=37/37 last=2026-11-19 missing=[]`**, and
covered equity picks rose 709 → 724. Only `SQ` (delisted on Yahoo) and `BK`/`BITF`
remain `no_data`, none of which the payload needs.

## 3. COMMODITY −3.57%: the emitter is `futures_momentum` SHORT, and it is already shut

**The finding.** One cell is essentially the entire class alpha:

| cell | n | wr | net %/trade | verdict |
|---|---|---|---|---|
| `futures_momentum` SHORT | 32 | **0.0%** | **−4.1338** | **KILL** (harm q=0.001) |
| `commodity_rsi_divergence` LONG | 6 | 50.0% | +0.367 | INSUFFICIENT_N |
| `commodity_momentum` SHORT | 4 | 25.0% | −0.0723 | INSUFFICIENT_N |
| `commodity_momentum` LONG | 3 | 0.0% | −1.1617 | INSUFFICIENT_N |
| `commodity_cross_momentum_winner` SHORT | 2 | 0.0% | −23.03 | INSUFFICIENT_N |
| class aggregate | 51 | — | −3.5066 | **KILL**, CI [−5.1259, −2.2468] |

Direction-sliced measurement confirms it: **COMMODITY/SHORT n=38, alpha −4.646%,
CI [−6.3005, −3.328]** — the lower bound is nowhere near zero. Every other slice in
the book is either positive or straddles zero. Its longer history agrees:
`at_pick_outcomes` holds 1,833 `futures_momentum` COMMODITY rows at −0.267%/trade,
14.3% win rate, last one 2026-06-12 — emission already stopped in June.

**Do we retire it?** Nothing to retire in code. The 2026-11-19 denylist work already
gates precisely this cell, checked directly:

```
class_gate_mode: positive_cells
futures_momentum SHORT -> denied='audit3 KILL: COMMODITY futures_momentum SHORT n=32 net=-4.1338%/trade (harm q=0.001)'
futures_momentum LONG  -> denied='… class gate: this cell is not CANDIDATE/PROVEN_T2 …'
commodity_rsi_divergence LONG -> denied='… class gate …'
health: 8 KILL strategy cells, 10 KILL symbol cells, 2 KILL classes, 0.0d old
```

So the answer to "should any be retired" is: the one that deserves retirement is
already blocked at emission, both per-cell and via the class gate, and the other
COMMODITY cells are `INSUFFICIENT_N` rather than proven — the class gate correctly
refuses them too. **No code change made**, deliberately: weakening or hard-coding a
name-level ban would discard the re-measurement path that paper picks (exempt from
the class gate) provide. What remains is historical rows, which should not be
rewritten; the −3.57% is a record of past emission, not a live claim.

## 4. My endorsement: `/audit3` — and explicitly not "money-ready"

Asked to label a recommendation among the three surfaces. Stated plainly:

**I endorse `findtorontoevents.ca/audit3` as the surface to trust for the question
"does any of this have edge?"** I do **not** endorse any asset class on any of the
three surfaces as ready for real money, based on today's numbers.

Justification, from this run (3,188 covered picks / 3,500):

| class | n | pick | hold | alpha | 95% CI | read |
|---|---|---|---|---|---|---|
| EQUITY | 724 | +0.031% | +0.037% | −0.007% | [−0.3595, +0.3396] | zero |
| FOREX | 116 | −0.111% | −0.074% | −0.037% | [−0.1086, +0.0408] | zero |
| ETF | 541 | −0.075% | +0.042% | −0.117% | [−0.3100, +0.0826] | zero |
| BOND | 34 | −0.275% | −0.166% | −0.109% | [−0.4305, +0.2305] | zero |
| CRYPTO | 1727 | −0.373% | +0.001% | −0.374% | [−0.7437, +0.0175] | negative lean (LONG −0.458%, CI excl. 0) |
| COMMODITY | 46 | −3.567% | +0.000% | **−3.567%** | **[−5.1259, −2.2468]** | proven harm |
| overall | 3188 | −0.266% | +0.012% | **−0.278%** | **[−0.5158, −0.0394]** | negative, CI excludes 0 |

The book as a whole underperforms simply holding the same instruments, and the
overall interval excludes zero. Not one class has an interval that clears zero on
the positive side. That is the honest reading and it is the reason for the endorsement
shape below.

* **`/audit3` — endorsed, and my primary recommendation** for anyone deciding
  whether to trust a strategy. It is the only one of the three that answers
  *selection* rather than luck: alpha versus direction-adjusted buy-and-hold over the
  identical window, Wilson/bootstrap intervals, q-values, DSR, an explicit
  `unmeasured` reason per class (`bar_coverage`), and a kill tribunal whose verdicts
  are enforced at emission. It also reports the uncomfortable numbers above instead
  of hiding them, which is the property that makes a dashboard worth reading.
* **`/audit` — endorsed as the product/pick feed, not as evidence of edge.** It is
  where the broad live book is, and it is the right place to see *what was picked*.
  Its own forward record has sat near a ~21% win rate; treat its picks as candidates
  to measure on `/audit3`, never as conclusions.
* **`/audit2` — not endorsed for any decision.** It is a narrow forward-observation
  view (`reports/forward_observations.jsonl` → per-hypothesis n, benchmark leg,
  intrabar, pods). It describes how observations were recorded, not whether a cell
  beats its benchmark.

Bottom line: **use `/audit3` to decide, `/audit` to browse, `/audit2` as context.
No class is money-ready today.**

## 5. Follow-up: the scheduled step was a no-op on its first CI run (fixed)

The first dispatched run (`44583198861`) reported the new step as **success** while
writing zero rows. The log:

```
ModuleNotFoundError: No module named 'pymysql'
##[warning]equity/etf/futures backfill failed (see log)
ERROR: cannot import DB deps (No module named 'pymysql'). Install pymysql ...
```

Cause: both `tools/backfill_daily_ohlcv.py` and `tools/fx_backfill.py` resolve
credentials through `tools/db_env`, which imports `pymysql`; the step's `pip install`
listed only `yfinance pandas`, and the alpha step's `pymysql` install runs *later*.
`continue-on-error: true` plus `|| echo "::warning"` kept the run green — the same
defect class as the alpha step fixed earlier in this series (missing driver swallowed
by `|| true`), which is why it was worth checking the log rather than the green tick.

**Fix** (`.github/workflows/audit3-ledger.yml`, PR #947 → main `03d5c8d2cac`):

* install `pymysql` with the vendor libs;
* hard-check `python3 -c "import pymysql, yfinance"` before doing any work;
* escalate step failures from `::warning` to `::error` so a silent no-op is visible;
* print `last_bar` and `age_days` for `equity_daily_ohlcv`, `etf_daily_ohlcv`,
  `futures_daily_ohlcv`, `fx_prices`, warning when a table exceeds the 5-day tolerance.
  That is the alarm that fires *before* a class becomes unmeasured again.

**Verified** on run `44583654634` — the first run in which the scheduled backfill
actually wrote data:

```
equity_daily_ohlcv     symbols=251 fetched=987 written=987 no_data=4
etf_daily_ohlcv        symbols= 59 fetched=236 written=236 no_data=0
futures_daily_ohlcv    symbols= 21 fetched= 68 written= 68 no_data=4
equity_daily_ohlcv     last_bar=2026-11-19 age_days=0
etf_daily_ohlcv        last_bar=2026-11-19 age_days=0
futures_daily_ohlcv    last_bar=2026-11-19 age_days=0
fx_prices              last_bar=2026-11-18 age_days=1
```

Lesson worth keeping: `continue-on-error` needs a matching loud signal. Otherwise
"green" means "nothing happened", and the gate silently reverts to `unmeasured`.
