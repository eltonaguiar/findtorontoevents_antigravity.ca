## Correction to the earlier plan

My previous plan (commit `85c521d29b`, now rebased onto main) stated:
> "every single one of the 50 crypto passes is a `clone_hl_copy_*` row with a suspicious identical-triple pattern"

This inherited a field-reading bug from the Blocker 2 analysis in `testreq.txt`. The actual HC gate in `audit_dashboard/hc_filter.js` checks **`strat_fwd_trades`** (the count of closed forward trades), not **`forward_trades`** (which is mis-named and actually holds the *win-rate × 100* value on clone rows).

When the real gate is applied:
- `strat_fwd_trades == 0` on every clone_hl_copy_* row (pipeline hasn't validated any)
- → Clones **self-reject** at the gate
- → 0/169 active picks pass the real HIGHFWWRABV55+SCOREABOVE50 gate on current data (per Codex running the JS filter directly)
- → The previous "50/50 passes" number was measured against the wrong field

**The `clone_hl_copy_*` rows do not bypass the HC gate. They fail it cleanly.**

What IS real and still a bug:

1. `elite_score`, `forward_wr`, `forward_validated` on clone rows are **populated from the OKX trader's self-reported WR scraped by `copy_trader_intel`** — not from our pipeline's closed-trade validation.
2. This makes clone picks display **`elite_grade: "A"` badges** in the general UI even though HC gate rejects them — a user-facing misrepresentation.
3. `clone_safety_mode: "EXEMPT_FROM_SAFETY_GATES"` is **orphan data** (no code reads it). Not an active bypass; just dead metadata.

## Fix applied in this commit

**File:** `copy_trader_intel/strategy_clone_generator.py:492-498`

**Before:**
```python
# Forward validation from original trader
"forward_trades": expected.get("win_rate", 0) * 100,
"forward_wr": expected.get("win_rate", 0),
"forward_validated": expected.get("win_rate", 0) >= 0.52,
# Edge & grading
"elite_score": min(int(expected.get("win_rate", 0.5) * 100), 100),
"elite_grade": "A" if expected.get("win_rate", 0) >= 0.70 else "B" if expected.get("win_rate", 0) >= 0.55 else "C",
```

**After:**
```python
# Forward validation (start at zero; pipeline earns these via closed trades)
# Trader's self-reported stats live in clone_expected_wr / clone_expected_pf below
# so the UI can display them as unvalidated expectations, separate from pipeline truth.
"forward_trades": 0,
"forward_wr": 0.0,
"forward_validated": False,
# Edge & grading — ungraded until pipeline validates from closed trades
"elite_score": 0,
"elite_grade": "UNGRADED",
```

The trader's marketing stats are already preserved at lines 510-511 (`clone_expected_wr`, `clone_expected_pf`), so the UI can display them separately as unvalidated expectations.

### Backwards compatibility

- Existing clone picks already in the ledger are unaffected; this change only touches new picks generated by future runs.
- `forward_validator.py` updates `forward_wr`/`forward_validated` when clone trades close, so clone picks with real edge will earn their grades over time — the pipeline's existing validation path does the work.
- Any UI filter that checks `elite_grade in ("A","B","C","D","F")` will skip `"UNGRADED"` — that's the correct behavior for an uncalibrated clone pick.
