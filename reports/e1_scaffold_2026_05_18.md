### The signal

SEC Form 4 filings report insider transactions. Transaction code **"P"** is an
*open-market purchase* — an officer or director buying shares with personal
capital. Code P is distinct from code A (grant/award), M (option exercise),
S (sale), F (tax withholding) — the bulk of insider activity is options
exercise and 10b5-1 plans, **NOT** code P. A *cluster* is 3+ DISTINCT insiders
filing a code-P purchase on the SAME ticker within a short rolling window.

- `cluster(D)` = >= 3 distinct insiders, code P, same ticker, within 10 days.
- `total_buy_usd` = summed code-P purchase notional across the cluster's
  insiders.
- `signal_z` = strictly-past rolling z-score of the cluster's `total_buy_usd`
  vs the ticker's own prior clusters. harness score field = `|signal_z|`.
- direction = **LONG only**. A cluster is unambiguously bullish revealed
  preference; insider open-market SELLING is far noisier (diversification,
  liquidity, tax) and is explicitly NOT used as a short leg.

**Causal mechanism:** insiders have a legal information advantage and a
revealed-preference signal — open-market buys with personal capital, when
*clustered*, are the strongest legal information event available. The edge
persists because the filings are noisy and require careful code-P filtering —
assembly cost is the only moat. A sound prior is NOT an edge.

### Small-cap stratification — pre-registered scope

The proposal is explicit (`new_strategy_proposals_2026_05_18.md` lines 491-492):
the cluster-buy signal is "likely arbitraged in mega-caps" — *"pre-register the
small-cap-stratified version only, not the full universe."* This module tests
**ONLY the small-cap cohort** — tickers whose market capitalisation is below
`SMALL_CAP_MAX_USD` ($2B) at cluster time. Mid- and large-cap clusters are
filtered out entirely; any name that has grown out of the small-cap band is
flagged `_excluded_large_cap` and contributes no records. The full-universe E-1
is deliberately **NOT** built and **NOT** pre-registered.

### Construction (legitimate density pattern from H-008/H-019/H-026/H-027)

- **FULL continuous-position LONG-only book** — insider clusters are sparse
  events; the harness needs 14-day-window density. Once a small-cap ticker
  forms a code-P cluster, EVERY (ticker, day) for the next 20 trading days is
  one resolved record. NO post-hoc `total_buy_usd` threshold, NO selection of
  "big" clusters. This is the H-008 continuous-hold density pattern, not
  threshold relaxation.
- **Strict no-look-ahead** — a Form 4 lags the transaction by up to 2 business
  days. The cluster is stamped at the LATEST filing date of its constituent
  purchases, becomes visible one day later, and a position on day D may see
  only clusters visible strictly before D; entry D; return realized over price
  close(D)->close(D+1).

### Data sources — free only

- **SEC EDGAR `data.sec.gov`** — submissions API + Form-4 ownership XML feed
  (free, no key, SEC-UA required). Code P = open-market purchase; A/M/S/F/G
  discarded.
- **yfinance** — free, no-key daily close series + `marketCap` scalar (drives
  the small-cap cut).
- **openinsider.com** — documented free scrapeable fallback aggregator; the
  canonical path is the primary SEC EDGAR feed.

No paid feed, no API key. If every free source fails the module degrades to a
clearly-labelled synthetic series and reports `UNTESTED-data-gap` — it never
fabricates a pass.

## How to run it

```bash
# full run (~30 small-cap-leaning equities) — writes the report
python tools/e1_insider_cluster_buy_research.py

# fast smoke (8 tickers)
python tools/e1_insider_cluster_buy_research.py --quick

# machine-readable verdict only
python tools/e1_insider_cluster_buy_research.py --json

# re-fetch free data, ignoring the cache
python tools/e1_insider_cluster_buy_research.py --refresh-cache
```

Output report: `reports/e1_insider_cluster_buy_research_2026-05-18.md`.
Data cache: `tools/cache/e1_insider_cluster_buy_cache.json`.

The verdict is one of `ADMISSIBLE`, `REJECTED`, or `UNTESTED-data-gap`. A gaudy
in-sample WR is NOT a pass — only the harness + post-cost verdict counts.

**Known data caveat:** a real per-insider code-P transaction tape requires
walking each Form-4 ownership XML (`ownershipDocument/nonDerivativeTable` for
`transactionCode == "P"`, `transactionShares * transactionPricePerShare`). That
bounded EDGAR XML walk is documented but not wired in this scaffold; until it
is, the honest verdict is likely `UNTESTED-data-gap`.

## Wiring Plan

E-1 is an **opt-in sidecar today** and stays that way until it clears the
harness gate. Per the CLAUDE.md Wire-Up Rule, here is the explicit wire-up path:

- **Target caller file:** `audit_trail/quality_gates.py`
- **Target function:** `passes_active_gate(...)` — the production pick gate.
  E-1 would contribute an `insider_cluster_buy` boolean + `total_insider_buy_usd`
  feature read by the gate for `asset_class == "EQUITY"` small-cap picks (and
  surface in `audit_trail/dashboard_generator.py::calculate_smart_score` as a
  scoring input).
- **Pre-wire-up harness-gate condition (HARD GATE — all must hold):**
  1. `tools/e1_insider_cluster_buy_research.py` must report
     `VERDICT: ADMISSIBLE` — `tools/edge_stability_harness.py::is_admissible()`
     returns `True`: `|eff| >= 0.30`, **same sign**, in `>= 3 of 5` walk-forward
     14-day windows, each window `>= 80` records.
  2. The post-cost gate must PASS — net edge retains `>= 60%` of gross after a
     15bps small-cap round-trip.
  3. The run must NOT be on a synthetic/offline fallback series — it must use a
     dense per-insider Form-4 code-P transaction tape (the EDGAR ownership-XML
     `nonDerivativeTable` walk).
  4. The result must hold within the **small-cap cohort** — the pre-registered
     scope. A full-universe pass is out of scope and does NOT satisfy this gate.
  5. A fresh **out-of-sample** re-test on data collected after the
     `data_sample_lock` must also clear (1)+(2).
  6. A deflated-Sharpe / SPA multiple-testing correction and operator sign-off.
- **If any condition fails:** archive the H-028 config, mark the registry row
  `REJECTED`, record the `next_step`, and **do NOT re-test the same
  construction on the same sample** (M-107). No wiring.

Until (1)-(6) all hold, E-1 has **zero production callers** and changes **zero
production behaviour**.
