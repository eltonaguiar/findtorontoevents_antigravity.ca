### The four defect classes caught this session (transferable lessons)

1. **Stale artifact.** 12.07 bp was a *real* measurement whose artifact was stale. Root cause: the
   run loop was gated on `TIINGO_API_KEY` even though the yfinance spread path needs no key, so a
   key-less re-run silently overwrote a good artifact with `SKIPPED_OFFLINE_OR_NO_KEY`. Fixed;
   artifact regenerated; tripwire added (`tests/test_m1_cost_provenance.py`).
2. **Subtraction-as-counting.** The tally `0/8/6` was carried through three documents and several
   summaries and was never counted. Doc 23 then replaced it with `0/9/2/3` computed as
   `14 − 9 − 2`, which could not name the third UNKNOWN. Root cause: `BLOCKED_MISSING_DATA` was
   treated as a fourth *bucket* when it is a **qualifier on UNKNOWN**. Honest count: `0/10/4`,
   then `0/11/3`.
3. **Green-while-wrong test.** `tests/test_edge_research_tally_consistency.py` passed 17 tests while
   a fourth document carried the stale tally, because it checked a **hardcoded dict of three
   paths**. A test that passes without examining the failing case is worse than no test: it
   *certifies* a false state. Now globs `docs/**/*.md` with a coverage guard (18 tests).
4. **Prose-as-evidence.** Two of my own defect reports were wrong because I read documentation prose
   instead of the artifact: I claimed `class_cost_20261122.json` had empty `classes` (it was
   populated and committed), and I flagged the programme's own `[SRC: ...]` annotations as foreign
   edits. Both were propagated before being checked.
