## PART 1 — Full Project Evaluation

### What's Working Well ✅

1. **`crypto_ml_edge` architecture** — Textbook-quality: LightGBM + triple-barrier labeling + walk-forward CV with purge/embargo + DSR gate + SHAP pruning + fractional differentiation (Lopez de Prado). This is the strongest foundation in the project.
2. **Regime router** — F&G + EMA20/50 + ADX + RSI-14 is correctly blocking dangerous trades (e.g., no shorts during panic).
3. **Cross-aggregator defensive guards** — Staleness (45min), correlation/concentration limits, rolling WR suspension, portfolio drawdown circuit breaker — all well-designed.
4. **Baby bundles emerging** — Keltner Compression (75% WR, 12 trades, Sharpe 11.31) and Kalman Trend (59% WR, 22 trades) are genuine forward-validated signals.
5. **Genome evolution** — Correctly discovered inverted FVG signals (raw FVG has 0% WR → inverting = contrarian alpha).

### TOP 12 PROJECT-WIDE TWEAKS — Ranked by Impact

#### TIER 1 — Do These First

**1. Fix the funding rate data pipeline** ⭐⭐⭐⭐⭐
System D's funding heatmap is **all nulls**. The `crypto_ml_edge` feature engine defaults to `0.0` when funding data is missing, neutering 3 of 17 features (`funding_rate`, `funding_zscore`, `funding_momentum`). Funding rate is crypto's most unique alpha source — fixing this alone could improve model accuracy and bring System D online.

**2. Consolidate to 3-5 validated systems, pause the rest** ⭐⭐⭐⭐⭐
**Keep:** `crypto_ml_edge` (best architecture), Claws of Doom (47.4% WR, salvageable), Keltner + Kalman baby bundles (promising forward data). **Pause:** Mercury2, Systems A/B/C/D/E, Ensemble. Spreading resources across 24 systems without validating any. Focus beats breadth.

**3. Add SHORT signal capability to the ML models** ⭐⭐⭐⭐⭐
`crypto_ml_edge` is binary long-only (`{0=no-trade, 1=long}`). In the current bear market (F&G=10, BTC -21% in 30 days), it produces zero useful signals. Add `label=-1` for shorts in the triple-barrier labeler. Doubles the opportunity set.

#### TIER 2 — Medium Impact

**4. Unify labeling across engines** ⭐⭐⭐⭐
`crypto_signal_engine` uses simple "price up = 1" → ~50% class balance. `crypto_ml_edge` uses cost-gated triple-barrier → 29% positive class. Standardize on triple-barrier.

**5. Add on-chain features** ⭐⭐⭐⭐
All 17 features are price/volume/sentiment — standard TA. Add: exchange net flows, whale wallet movements, DEX/CEX volume ratio, stablecoin supply changes. Free APIs: CryptoQuant, Glassnode free tier.

**6. Implement dynamic regime-scaled position sizing** ⭐⭐⭐⭐
Regime router is binary (allow/block). Instead: extreme fear → 25% position (contrarian), strong trend (ADX>30) → 100% in trend direction, range (ADX<20) → 50% mean-reversion only.

**7. Restore the DSR gate to 0.95 for production** ⭐⭐⭐⭐
`MIN_DSR_PROBABILITY` was lowered from 0.80 to 0.75 "to let more signals through." This defeats the purpose of the gate.

#### TIER 3 — Refinements

**8. Implement inverse signals for consistent losers** ⭐⭐⭐
smart_money_fvg has 0% WR over 9 trades. A consistently wrong signal IS a signal — invert it. Genome evolution already discovered this.

**9. Add walk-forward validation to ALL systems** ⭐⭐⭐
Only `crypto_ml_edge` has proper walk-forward CV. The other systems backtest on the same data they train on.

**10. Reduce the coin universe** ⭐⭐⭐
Scanning 250+ coins dilutes signal quality. Focus on top 20 by volume where data quality and liquidity are highest.

**11. Add time-of-day features** ⭐⭐
Crypto has strong session effects (Asia/EU/US). Add `hour_sin`, `hour_cos`, `is_us_session`, `day_of_week` to the feature engine.

**12. Regime-conditional system weighting in aggregator** ⭐⭐
Current scoring: `confidence × WR × Sharpe_weight`. Better: weight by **regime-specific WR**.

### Root Cause: Missing Predictors

**The #1 bug:** StockTwits (194 predictions) and Reddit (87 predictions) scrapers do raw `INSERT INTO predictions` SQL instead of calling `insert_prediction()` from `db.py`. This bypasses `_upsert_predictor()`, so their predictor_id never gets an entry in the `predictors` table. Only TradingView uses the correct function path.
