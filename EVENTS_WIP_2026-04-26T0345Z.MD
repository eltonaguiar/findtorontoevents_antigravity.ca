## Remaining steps

### Priority 1 — Fix SITC production blocker
- **Problem:** `singleinthecity.ca/wp-json/tribe/events/v1/events` returns 403 from GitHub Actions runners.
- **Likely fix:** add `Referer: https://singleinthecity.ca/events/`, `Origin: https://singleinthecity.ca`, and `Accept: application/json, text/plain, */*` headers in `SingleInTheCityScraper.__init__`. If still 403, fall back to the public `/events/` HTML page (Tribe also embeds events in `data-tribe_events_calendar` attributes) or use Scrapling's TLS-fingerprinted fetcher (already a dep in `dating_events_scraper.py`).
- **Effort:** small (≤30 min).

### Priority 2 — Retire or reconnect the SQL silo
- Decision needed: retire `ejaguiar1_events` (delete the read path, document on /audit page) **or** rewire the frontend to read from SQL with `events.json` as fallback. Until decided, the silo continues to drift.
- **Effort:** retire = 1 hour doc/decommission; reconnect = 2–4 days backend work.

### Priority 3 — React #418 hydration mismatch
- Next.js SSR HTML doesn't match initial CSR render on findtorontoevents.ca. Non-fatal but adds visible jank and trips error monitoring.
- **Likely culprits:** date formatting that uses `new Date()` differently on server vs. client (Toronto vs. UTC), or the `__EVENTS_JSON_PATH__` shim in `index.html` running before hydration completes.
- **Effort:** medium — requires reproducing locally, bisecting components.

### Priority 4 — Eventbrite + Meetup official APIs
- Currently scraping HTML; both have official APIs (Eventbrite OAuth, Meetup GraphQL). Switching unlocks +3,500–5,000 events with better rate-limit safety and richer metadata (registration counts, organizer ratings).
- **Effort:** medium per integration. Requires API keys (free for both; Eventbrite has been deprecating public search though).

### Priority 5 — AI description enrichment
- Audit identified 53.8% of SQL store rows missing descriptions. Same issue likely in `events.json` for low-effort sources.
- **Approach:** nightly batch — for any event with missing/short description and a working URL, fetch the page, summarize via Claude Haiku (low cost), populate `description` field in `events.json`. Cache by URL hash to avoid re-summarizing.
- **Effort:** medium. ~1–2 days.

### Priority 6 — Festival sub-event capture
- Audit identified 5 major 2026 festivals (FIFA WC, Caribana, TIFF, CNE, Nuit Blanche) where only the marquee event is captured. Sub-events (panels, fan-fest, daily programming) are scattered across platforms.
- **Approach:** dedicated scrapers per festival's official sub-event listing or schedule page. Manual-curated overrides as bridge.
- **Effort:** large — recurs every year for the 5 festivals.

### Priority 7 — University events (UofT / York / TMU)
- Audit estimates 200–500 events/yr; current coverage minimal.
- UofT has an existing scraper (`UofTEventsScraper`); audit signal suggests it may be under-producing. Investigate first before adding York/TMU.

### Priority 8 — Luma (tech / creator vertical)
- 500–1,000 events/yr, growing 5x. Currently 0 in catalog.
- `LumaScraper` already exists with `LUMA_API_KEY` env var support — needs API key provisioned.

## Areas of improvement (technical debt)

### Linter/hook stripping `unified_scraper.py` edits
Two times during this work, edits to `tools/scrapers/unified_scraper.py` (registering new scrapers) were silently reverted by what appears to be an auto-formatter / hook on the working copy. The edits stuck inside a coherent commit, but standalone `Edit`-tool changes did not. **Worth investigating** what's running and whether it can be configured to leave new imports alone.

### Test allowlist concentration
`playwright.config.ts` has 100+ explicit `testMatch` entries — adding a new test file requires editing the config. Could be replaced with a glob (`tests/**/*.spec.{ts,js}`) at the cost of running more tests by default.

### `events.json` size
At 10K events the file is now ~12 MB. Currently fetched in a single request on page load. Acceptable for desktop, but on mobile this is meaningful. Consider:
- Server-side filtering by date range / category (requires a real backend, not the static FTP setup)
- Splitting `events.json` into `events-upcoming.json` + `events-past.json`
- Gzip-on-FTP (50webs may or may not support; verify)

### Categorization noise
Reviewing TPL output: `_categorize` sometimes adds inappropriate top-level categories (e.g., "Sports" or "Nightlife" for a senior tech-help session) due to loose substring matches in `BaseScraper.categorize_event`. Inherited issue, not introduced by this work, but visible now that 5K+ TPL events flow through.

### CI smoke flakiness
Pre-existing `tests/sports_betting_js_errors.spec.js` `smoke` job hits live production and fails intermittently on third-party 503s. Unrelated to events but worth addressing — same pattern of allowlisting third-party noise should apply.
