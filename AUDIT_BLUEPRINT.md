- **Engine:** InnoDB, utf8mb4_unicode_ci

## Asset Class Classification

Every table has an `asset_class` column:

| Value | Detection Rule | Examples |
|-------|---------------|----------|
| `CRYPTO` | Ends with USDT/BTC/ETH/BUSD/USDC or known crypto base | BTCUSDT, ETHUSDT, SOLUSDT |
| `FOREX` | 6-char pair from major currencies, or known forex pairs | EURUSD, GBPJPY, XAUUSD |
| `EQUITY` | Default for stock tickers | SPY, AAPL, QQQ |
| `PENNY_STOCK` | Source is penny_picks or price < $5 | OTC/PINK exchange stocks |
| `MEMECOIN` | Known memecoin base symbols | DOGE, SHIB, PEPE, BONK, FLOKI, WIF |
| `SPORTS` | Sports betting systems | (future) |
| `UNKNOWN` | Cannot determine | Fallback |

**Implementation:** `derive_asset_class_ext()` in `audit_trail/backfill.py` (extended version) and `derive_asset_class()` in `audit_trail/recorder.py` (core version).

## Dedup Strategy

```
SHA-256( symbol | direction | entry_price_8dp | timestamp_rounded_to_5min )
```

- **Column:** `dedup_hash CHAR(64) UNIQUE`
- **Pattern:** `INSERT IGNORE` (SQLite) / `INSERT IGNORE` (MySQL) — silently skip duplicates
- **Window:** 5-minute rounding prevents near-duplicate signals from the same source

## Filter Funnel

The aggregator applies these gates in order. Each rejection is logged to `at_filter_log`:

| Gate | Reason | What it checks |
|------|--------|----------------|
| 1 | `demoted_system` | Source system's rolling WR below threshold |
| 2 | `wr_suppressed` | Strategy-level WR guard |
| 3 | `banned_strategy` | Blacklisted strategy names |
| 4 | `staleness` | Signal older than freshness window |
| 5 | `no_consensus` | Not enough systems agree |
| 6 | `concentration_cap` | Too many picks for one symbol |
| 7 | `regime_mismatch` | Market regime incompatible with pick direction |
| 8 | `daily_cap` | Maximum daily picks reached |

## Validation Rules

| Rule | Check | Rejection |
|------|-------|-----------|
| Symbol required | `symbol` or `pair` must be non-empty | Skipped silently |
| Direction valid | Must be LONG/SHORT/BUY/SELL | Skipped silently |
| Price positive | `entry_price > 0` | Skipped silently |
| Confidence range | `0.0 ≤ confidence ≤ 1.0` | Rejected with error |
| Timestamp sanity | Not more than 5 min in the future | Rejected with error |
| Dedup uniqueness | SHA-256 hash must be unique | `INSERT IGNORE` (silent skip) |

## Graceful Degradation

All audit calls in aggregator.py and discord_notify.py are wrapped:

```python
try:
    from audit_trail import start_run, record_raw_pick, ...
    _HAS_AUDIT = True
except ImportError:
    _HAS_AUDIT = False

# Usage:
if _HAS_AUDIT and _audit_run_id:
    try:
        record_raw_pick(sys_name, pick, _audit_run_id)
    except Exception:
        pass  # Never crash the aggregator
```

If `audit_trail` package is missing or the DB fails, the aggregator runs normally.

## MySQL Migration Steps

1. **Create tables:** Run `audit_trail/mysql_schema.sql` against `ejaguiar1_stocks`
2. **Import backfill:** Run `audit_trail/backfill_import.sql` (or regenerate with `backfill.py`)
3. **Switch driver:** Update `audit_trail/db.py` to use `pymysql` instead of `sqlite3`
4. **Update workflow:** Point aggregator to MySQL instead of local SQLite

```sql
SELECT source_system,
       COUNT(*) as total,
       SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END) as wins,

             NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END), 0), 1) as wr_pct

WHERE status IN ('WON','LOST')
```

```sql
SELECT asset_class, COUNT(*) as trades,
       ROUND(AVG(pnl_pct), 2) as avg_pnl
```

### Investigate why a backtest strategy looked good

### Realized vs Unrealized P/L

**Closed picks (realized):** `pnl_pct` in `at_raw_picks` or `final_return_pct` in `consensus_tracked`.

**Open picks (unrealized):** Two approaches:

1. **Tables with live price tracking** — `consensus_tracked.current_price` and `tracked_portfolio_picks.current_price` are updated by periodic scripts. Use `current_return_pct` directly.

2. **Tables without live prices** — `at_raw_picks` stores `entry_price` but not current price. To get unrealized P/L, pull the live market price from an API and compute:
   - LONG: `(current_price - entry_price) / entry_price * 100`
   - SHORT: `(entry_price - current_price) / entry_price * 100`

> **Note:** There is a lag between database writes. Realized P/L is most accurate. Unrealized P/L from `current_price` fields may be minutes to hours old.

#### Strategy performance for a specific dashboard

```sql
-- Example: Alpha Engine dashboard — autocorrelation_exploiter (10 forward picks)
SELECT strategy,
    COUNT(*) AS picks,
    SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END) AS wins,
    SUM(CASE WHEN status='LOST' THEN 1 ELSE 0 END) AS losses,
    ROUND(SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*100.0/
          NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END),0),1) AS win_rate,
    ROUND(AVG(pnl_pct),2) AS avg_pnl,
    ROUND(SUM(CASE WHEN status='WON' THEN ABS(pnl_pct) ELSE 0 END)/
          NULLIF(SUM(CASE WHEN status='LOST' THEN ABS(pnl_pct) ELSE 0 END),0),2) AS profit_factor
FROM at_raw_picks
WHERE source_system = 'alpha_engine' AND strategy = 'autocorrelation_exploiter'
GROUP BY strategy;
```

#### Systems with 50+ forward tests — full scorecard

```sql
SELECT
    source_system,
    strategy,
    COUNT(*) AS picks,
    SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END) AS resolved,
    -- Win Rate
    ROUND(SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*100.0/
          NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END),0),1) AS win_rate_pct,
    -- Total P/L
    ROUND(SUM(COALESCE(pnl_pct,0)),2) AS total_pnl_pct,
    -- Profit Factor
    ROUND(SUM(CASE WHEN status='WON' THEN ABS(pnl_pct) ELSE 0 END)/
          NULLIF(SUM(CASE WHEN status='LOST' THEN ABS(pnl_pct) ELSE 0 END),0),2) AS profit_factor,
    -- Max single-trade loss (drawdown proxy)
    ROUND(MIN(pnl_pct),2) AS worst_trade_pct,
    -- Avg Win / Avg Loss
    ROUND(AVG(CASE WHEN status='WON' THEN pnl_pct END),2) AS avg_win,
    ROUND(AVG(CASE WHEN status='LOST' THEN pnl_pct END),2) AS avg_loss,
    -- Expectancy = (WR * AvgWin) - ((1-WR) * |AvgLoss|)
    ROUND(
        (SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*1.0/
         NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END),0))
        * AVG(CASE WHEN status='WON' THEN pnl_pct END)
        - (1 - SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*1.0/
         NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END),0))
        * ABS(AVG(CASE WHEN status='LOST' THEN pnl_pct END))
    ,2) AS expectancy_pct
FROM at_raw_picks
WHERE status IN ('WON','LOST','OPEN') AND entry_price > 0
GROUP BY source_system, strategy
HAVING picks >= 50
ORDER BY total_pnl_pct DESC;
```

#### Forward-test vs backtest comparison (do backtests hold up?)

```sql
SELECT fw.strategy, fw.forward_picks, fw.forward_wr, fw.forward_pf,
       bt.backtest_trades, bt.backtest_avg_pnl,
       ROUND(fw.forward_wr - COALESCE(bt.backtest_wr, fw.forward_wr), 1) AS wr_decay
FROM (
    SELECT strategy, COUNT(*) AS forward_picks,
        ROUND(SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*100.0/
              NULLIF(SUM(CASE WHEN status IN ('WON','LOST') THEN 1 ELSE 0 END),0),1) AS forward_wr,
        ROUND(SUM(CASE WHEN status='WON' THEN ABS(pnl_pct) ELSE 0 END)/
              NULLIF(SUM(CASE WHEN status='LOST' THEN ABS(pnl_pct) ELSE 0 END),0),2) AS forward_pf
    FROM at_raw_picks WHERE status IN ('WON','LOST')
    GROUP BY strategy
) fw
LEFT JOIN (
    SELECT strategy, COUNT(*) AS backtest_trades,
           ROUND(AVG(pnl_pct),2) AS backtest_avg_pnl,
           ROUND(SUM(CASE WHEN status='WON' THEN 1 ELSE 0 END)*100.0/
                 NULLIF(COUNT(*),0),1) AS backtest_wr
    FROM bt_backtest_trades WHERE pnl_pct IS NOT NULL
    GROUP BY strategy
) bt ON fw.strategy = bt.strategy
WHERE fw.forward_picks >= 5
ORDER BY fw.forward_picks DESC;
```
