AI Product Packaging Overview

Packaging Notice: ServiceNow's AI packaging evolved to Foundation, Advanced, and Prime tiers around April 2026 (replacing the prior five-tier model). Last verified: October 2026. Entitlements are contract-specific—what is "included" vs. "add-on" varies by agreement. The table below reflects publicly documented capabilities; your instance may differ. Confirm with your ServiceNow account team.

ServiceNow's current product packaging uses three AI-native tiers: Foundation, Advanced, and Prime. These tiers differ primarily by the level of AI autonomy, process depth, and customization rights. All tiers include core AI enablers such as Now Assist (generative AI skills), Predictive Intelligence, Virtual Agent, AI Control Tower, and Workflow Data Fabric basics, with progressive capability increases. A "module" in ServiceNow typically means a navigation item under an Application Menu (or, more broadly, a scoped application with its own tables, logic, and UI). An "AI module" usually means enabling and configuring AI capabilities (Predictive Intelligence models, Now Assist skills, or AI Agents) and optionally wrapping them in a custom scoped app for specific use cases.

The Three Tiers

Tier AI Focus Key Additions (publicly documented) Typical Fit

Advanced Agentic workflows that synthesize context and automate steps Full ITIL processes (Change, Problem, Major Incident, On-Call), Process Mining, Platform Analytics Advanced, AI Voice, higher Assist allocation, OOTB agentic task execution Mature operations needing deeper processes and contextual automation

Shared across tiers (with variations in depth/allocation): Now Assist, Moveworks conversational layer, AI Control Tower (governance/observability), Workflow Data Fabric, and RaptorDB Standard for performance. Usage is often metered via "Assists" (consumed per skill/agent run, with tier allocations and top-up options). Only Prime unlocks building truly net-new custom skills and agents. Exact Assist allocations are contract-specific; the page previously showed illustrative ranges which have been removed.

Foundation – Setup Guide

  • Confirm licensing and instance version (Zurich or later preferred for full AI features).
  • Activate relevant plugins via System Applications > All Available Applications (or the Store): Now Assist for ITSM (or relevant product), Predictive Intelligence (com.glide.platform_ml and related), Virtual Agent.
  • Open Now Assist Admin (or AI Admin Hub in newer releases) > Features/Skills. Select a workflow (e.g., Technology) and activate skills such as Incident Summarization or Reply Generation via the guided setup: choose triggers/inputs, display locations (in-product, Now Assist panel, or both), and roles.
  • For Predictive Intelligence: Navigate to Predictive Intelligence > Homepage or Classification > Solution Definitions. Create a solution definition (e.g., classification for assignment group based on short description), filter high-quality historical data (ideally 30k–300k clean records), submit for training, validate accuracy, and activate. Training typically runs on ServiceNow’s training service and returns the model.
  • Create Application Menu + Modules if you need custom navigation: System Definition > Application Menus (new) → related Modules (link type: List of Records, Form, etc., with roles and order).
Expected benefits: Faster agent productivity (summaries reduce reading time), basic auto-routing/categorization, higher first-contact resolution, and quick ROI with lower cost and complexity. Ideal for measurable but contained gains without major process changes.

Advanced – Setup Guide

Build on Foundation steps, then:

  • Activate additional process plugins (Change, Problem, Major Incident, On-Call) and Process Mining / Platform Analytics Advanced.
  • In AI Admin Hub / AI Agent Studio, enable and configure OOTB agentic workflows (agents that complete defined multi-step tasks while working alongside humans).
  • Set up Process Mining to analyze and optimize existing processes; use Platform Analytics for deeper KPI tracking.
  • Configure higher Assist allocations and AI Voice where relevant.
  • Extend modules or workspaces (via App Engine Studio or UI Builder) to surface agentic outcomes and analytics.
Expected benefits: End-to-end automation of process steps, contextual insights that reduce manual handoffs, process optimization visibility, and stronger efficiency gains (often larger MTTR reductions and higher deflection). Supports more complex operations while remaining largely configuration-driven.

Prime – Setup Guide

Build on the above, then:

  • Use AI Agent Studio and Now Assist Skill Kit to create net-new custom agents and skills from natural-language instructions or detailed prompts. Define single-responsibility agents, tools, and orchestration.
  • Configure advanced governance in AI Control Tower (policies, observability, external AI if licensed separately).
  • Leverage AI Action Fabric (A2A/MCP) for multi-agent or external system collaboration.
  • Build custom scoped applications (Studio or App Engine Studio) that consume the agents via APIs or flows.
  • Implement robust testing, evaluation (prompt testing, acceptance rates), and monitoring.
Expected benefits: Autonomous execution of multi-step or role-level work, highly tailored domain AI, maximum scalability, and transformative productivity or cost reduction for mature organizations. Highest potential ROI but requires strong data, governance, and change management.

Setting Up a Module (Application + Navigation) from Scratch

  • Prefer scoped applications for isolation, upgrade safety, and maintainability.
  • Use App Engine Studio (low-code, guided) or ServiceNow Studio (more developer-oriented): Create App → define name/scope/roles → add tables (data model) → forms/lists/workspaces → Flow Designer automation → security (roles + ACLs).
  • Add navigation: Create or use an Application Menu, then Modules (Title, Order, Link Type such as List of Records with filter, Roles for visibility). Modules appear in the All menu under the parent application.
  • For AI specifically, the “module” is often the activated skills/agents surfaced in workspaces, the Now Assist panel, or custom pages, rather than purely custom tables.

Architecture / Implementation Plan from Scratch (Cost & Performance Under Control)

Follow a phased, value-first approach. Prefer configuration over heavy customization, OOTB capabilities first, and measurable KPIs.

Envision & Discovery

Define SMART outcomes and KPIs (e.g., 30–50% MTTR reduction, Assist acceptance rate, deflection rate, hours saved). Audit data quality (critical for Predictive Intelligence; clean, labeled historical data is non-negotiable). Map current processes, stakeholders, and governance needs (AI CoE / Control Tower). Assess current tier fit and licensing. Cost control: Limit scope to high-value use cases. Performance: Identify data volume and quality early.

Design

Align to CSDM for CMDB/services. Design scoped apps, roles/ACLs, integrations (Integration Hub preferred), and UI (workspaces preferred over classic forms where possible). Decide model providers (Now LLM vs. third-party for cost/performance trade-offs). Plan Assist metering and usage monitoring. Architecture layers: Presentation (UI/workspaces), Application (flows, scripts, agents), Data (tables + CMDB). Cost/Performance: OOTB first; index frequently queried fields; plan table rotation/archiving; stagger jobs; consider RaptorDB for scale.

Build (Phased MVP)

Start with Foundation-level skills and core processes. Activate plugins, train models in a non-production clone, configure skills via Admin Hub guided setup, build simple flows/agents. Use App Engine Studio for rapid app/module creation. Implement security and basic testing. Cost control: MVP first, expand based on adoption. Performance: Validate in sub-prod; avoid inefficient GlideRecord loops or heavy client scripts.

Test, Deploy & Change Management

Automated testing + UAT. Train-the-trainer approach. Phased rollout (e.g., pilot groups). Monitor transaction times, slow queries, semaphore waits, and Assist consumption. Cost/Performance: Fix bottlenecks before full production; use Performance Analytics dashboards.

Optimize & Scale

Continuous monitoring (AI usage analytics, process mining, system diagnostics). Retrain models on schedule. Expand to Advanced/Prime capabilities only where justified by metrics. Govern via AI Control Tower. Cost control: Right-size licenses and Assist pools; retire unused customizations. Performance: Ongoing indexing, archiving, and query optimization.

Overall expected benefits (when executed well): Significant productivity gains (agent time saved via summaries and drafting), reduced resolution times, higher automation/deflection rates, better process visibility, and scalable AI that compounds with clean data and governance. Cost and performance stay controlled by starting small, preferring OOTB, measuring rigorously, and treating data quality and governance as first-class concerns.

For the latest entitlement details, plugin names, and exact Assist allocations, consult your ServiceNow account team or official product documentation, as packaging and feature availability evolve. Start with a non-production instance and clear success metrics for the safest path.

Monitoring, Governance & Quota Management

Operationalizing AI at scale requires observability, cost control, and governance. This section covers the essentials.

AI Control Tower

AI Control Tower is the centralized governance and observability hub for all AI capabilities across the platform. It is included in all tiers with progressive depth.

  • Model Inventory: Catalog of all Predictive Intelligence models, Now Assist skills, and AI Agents deployed in the instance.
  • Performance Monitoring: Accuracy, drift, latency, and adoption metrics per model/skill.
  • Usage & Quota Tracking: Real-time Assist consumption by skill, agent, user, and department. Dashboards show allocation vs. usage with trend lines.
  • Alerting & Thresholds: Configure alerts for quota overage (e.g., >80% monthly Assist consumption), model accuracy drift, skill failure rates, and latency spikes.
  • Policy Enforcement: Define allowed model providers (Now LLM vs. third-party), data residency rules, and approval workflows for new custom skills (Prime).
  • Audit Trail: Immutable log of all AI actions, configurations, and governance decisions for compliance.
Setup: Navigate to AI Control Tower > Overview. Enable Assist Metering and configure Alert Policies for quota thresholds. Assign ai_control_tower_admin and ai_control_tower_viewer roles.

Performance & Reliability Monitoring

  • Skill/Success Metrics: Acceptance rate (user accepts AI suggestion), edit rate, time-to-accept, fallback rate.
  • Model Health: Accuracy, precision/recall, F1, drift detection (data distribution shift), retraining cadence.
  • Latency & Availability: P50/P95/P99 response times for Now Assist panel, Virtual Agent, and AI Search. SLA targets typically <2s for summaries, <5s for generation.
  • System Impact: Monitor transaction times, semaphore waits, and DB load from AI workloads via System Diagnostics > Stats and Performance Analytics.

Governance Best Practices

  1. Establish an AI Center of Excellence (CoE) with representatives from IT, Security, Legal, and Business Units.
  2. Define AI Policy: approved use cases, data classification handling, human-in-the-loop requirements, and escalation paths.
  3. Implement Change Management for all AI config changes (skill activation, model retraining, agent deployment).
  4. Schedule Quarterly Reviews: quota burn, model performance, skill adoption, and ROI measurement.
  5. Document Data Lineage for all training data used in Predictive Intelligence and custom skills.

Now Assist Skill Kit (AI Skill Kit) — Practical Implementation

Why this matters: NASK (now also called AI Skill Kit) turns ServiceNow AI from "here are OOTB summaries" into "here is a real button on an Incident form that drafts a resolution note, classifies the ticket, or checks policy compliance." This section gives you a buildable implementation path.

Build Your First Useful AI Button: "Draft Resolution Notes" on Incident

Business outcome: An agent opens an Incident, clicks Draft Resolution Notes, and receives a draft resolution based on work notes, short description, CI, and related knowledge.

Prerequisites

  • Confirm the instance has the required AI entitlement and the Otto/AI Skill Kit plugins are installed or updated through Application Manager.
  • Confirm the user has the appropriate Now Assist/AI Skill Kit roles.
  • Use a non-production instance first.

Step-by-Step Implementation

  1. Create the skill: Go to Now Assist Skill Kit / AI Skill Kit → Create new custom skill → Name: Draft Incident Resolution Notes.
  2. Add inputs from the Incident record: short_description, description, work_notes, cmdb_ci, priority. Keep inputs limited to fields that genuinely improve the output.
  3. Write a grounded prompt with explicit rules (see prompt template below).
  4. Add useful tools:
    • Retriever to search relevant KB articles or known-error records.
    • Script tool to fetch recent related Incidents for the same CI.
    • Decision node to skip the retriever when the Incident has no CI or insufficient description.
    NASK supports retrievers, scripts, subflows, flow actions, decision nodes, and chained skills.
  5. Test properly: Use the skill's Test prompt area. Inspect both the Grounded prompt (actual prompt + tool output sent to the model) and Tools (each tool's request and response). This is the correct debugging loop; do not rely only on whether the final answer "looks good."
  6. Deploy as a UI Action: Choose UI Action as deployment target → Select incident table → NASK generates a UI Action with the skill invoked from its Script field. By default, output appears as an informational message. For a more useful version, modify the UI Action to write the draft into a field such as close_notes, work_notes, or a custom u_ai_draft_resolution field—but require agent review before saving.
  7. Control access: Activate the skill in Now Assist Admin console → Assign the role configured during activation → Verify UI Action is active and visible to intended roles. ServiceNow identifies skill activation, role assignment, and UI Action activation as common reasons a button does not appear.

Prompt Starting Point

You are assisting an IT service desk agent.

Using only the provided Incident data and retrieved knowledge, draft a resolution note.

Rules:
- Do not invent facts, root causes, or actions.
- If information is insufficient, say exactly what is missing.
- Use clear, professional language suitable for an Incident record.
- Separate: Summary, Actions Taken, Root Cause, Follow-up.

Incident data:
Short description: {{short_description}}
Description: {{description}}
Work notes: {{work_notes}}
Configuration item: {{cmdb_ci}}
Priority: {{priority}}

Retrieved knowledge:
{{retrieved_articles}}

Acceptance Criteria

  • Button appears only for authorized fulfillers.
  • Output is clearly labeled as an AI draft.
  • Agent can edit before saving.
  • No automatic update to a customer-facing field without approval.
  • Test cases cover: empty work notes, missing CI, unrelated KB results, sensitive data, and long ticket histories.

Real AI Agent Example: "Incident Triage Assistant"

Business outcome: When a P1/P2 Incident is created, the agent gathers context, identifies likely related records, proposes a category and assignment group, and creates a draft investigation summary for human approval.

  1. Define the job narrowly: Not "resolve incidents" but "Prepare a triage package for high-priority Incidents."
  2. Create the agent: AI Agent Studio → Create and manage → AI agents → Choose Chat for internal agent → Define specialty, goals, and limits.
  3. Set security first: Define who can invoke it, which tables/fields it can read. Ensure ACLs—not only agent instructions—control data access.
  4. Add modular tools: Get Incident Details, Find Similar Incidents, Search Known Errors, Get CI Health, Draft Triage Summary. Custom NASK skills can be published and added as tools.
  5. Add a trigger: Trigger on Incident creation where priority is P1 or P2. Do not trigger on every Incident initially.
  6. Require human approval: The agent may create a draft summary and recommendation. It should not automatically reassign, change priority, close, or notify executives until accuracy is proven.
  7. Test and monitor: Use AI Agent Studio's test capability. Track: correct category, correct assignment-group recommendation, useful similar-record retrieval, false-positive escalations, user acceptance.

Production Readiness Checklist & Best Practices

Every AI feature should pass this checklist before broad rollout:

Production-Readiness Checklist

  • Business owner and process owner identified.
  • Intended users and roles defined.
  • Input data sources documented.
  • ACLs reviewed.
  • Prompt and tool outputs tested with real, representative records.
  • Grounded prompt and individual tool outputs inspected.
  • Human approval required for consequential actions.
  • Sensitive-data handling reviewed.
  • Failure path defined.
  • Usage, acceptance, corrections, and cost monitored.
  • Rollback/disable procedure tested.
  • Users trained on what the AI does—and does not—do.

Best-Practice Principles

  • Start with one painful, frequent, low-risk task.
  • Use OOTB before custom.
  • Ground outputs in ServiceNow data and knowledge.
  • Keep skills small and modular.
  • Make the AI output editable.
  • Never let generated text auto-publish without review.
  • Use ACLs and role-based activation, not prompts, for security.
  • Log enough to debug, but not sensitive content unnecessarily.
  • Measure acceptance and correction rate, not just usage.
  • Treat every prompt, tool, model, and knowledge change as a production change.

Security & Privacy Requirements (Operational)

  • Document what data is sent to model providers and under what agreements.
  • Enforce data residency and retention controls per contract.
  • Implement PII/PHI/PCI handling and redaction before data reaches the model.
  • Role-based access to AI outputs, prompts, logs, and training datasets.
  • Approval controls for enabling AI on sensitive tables (HR, Healthcare, Financial, Security).
  • Rule: AI must not bypass ACLs, data privacy policies, or records-management requirements.
  • Separate treatment for regulated data domains with dedicated review gates.

Model Evaluation Framework

  • Maintain a labeled evaluation set for each skill.
  • Human review rubrics: factual accuracy, completeness, tone, policy compliance, safety.
  • Golden datasets for regression testing after prompt, model, or configuration changes.
  • Track rejected suggestions and edits (correction rate).
  • Separate metrics for classification models (accuracy/F1) vs. generative skills (acceptance, edit rate, hallucination flags).

Cost Model Nuance

Distinguish between:

  • Entitlement/licensing cost (contract)
  • Consumption cost (Assists)
  • Integration and data-preparation cost
  • Evaluation and human-review cost
  • Operational monitoring cost
  • Retraining and maintenance cost

The biggest cost lever is usually use-case selection and human-review design—not just disabling unused skills or caching.
