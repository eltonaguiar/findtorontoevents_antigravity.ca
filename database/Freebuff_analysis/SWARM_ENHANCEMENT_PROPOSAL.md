## Executive Summary

The existing swarm infrastructure (`tools/swarm/`) is **production-grade**: 50+ agent personas, multi-engine consensus, anti-hallucination contracts, audit trails, session chaining. However, **zero of the current swarm prompts** target the core prediction pipeline — they audit PRs, review frontend bugs, and assess static performance snapshots.

This proposal maps **16 new swarm areas** directly onto the prediction pipeline's highest-leverage intervention points, organized by where they would surface on the audit dashboard.

#### 3.1 `strategy_kill_review.md` — Automated Kill/Keep Triage

**Personas:** `tier-gate-keeper`, `forex-diagnostic-surgeon`, `commodity-specialist`, `crypto-specialist`, `equity-specialist`

**Triggers:** Weekly cron (or after every `production_scanner.py` cycle)

**What it does:**
1. Reads `audit_trail/data/universal_resolved_picks.json`
2. Computes per-strategy: WR (last 50 trades), PF, MDD, Sharpe, n
3. Flags strategies meeting kill criteria:
   - WR < 40% with n ≥ 30 → **KILL**
   - PF < 0.8 with n ≥ 30 → **KILL**
   - PF > 5.0 with n < 10 → **FLAG** (overfit)
   - Zero picks in 14+ days → **STALE** (orphan)
4. For FOREX strategies (PF 0.27): applies `mutate-before-kill` protocol via `forex-diagnostic-surgeon`
5. Outputs JSON kill-list for `audit_trail/quality_gates.py` to consume

**Dashboard surfacing:** New panel on `/audit` — "Strategy Health Triage" with kill/stale/flag counts

**Estimated impact:** +3-5% WR (removing anti-predictive strategies from consensus)

**Effort:** 3h (prompt + integration with `quality_gates.py`)

#### 3.2 `db_health_monitor.md` — Database Integrity Watchdog

**Personas:** `data-quality-auditor`, `performance-debugger`

**Triggers:** Every 6 hours

**What it does:**
1. Runs the Wave 0 fast queries (`tools/wave0_fast_queries.py`)
2. Checks:
   - OPEN row count vs baseline (alerts if >27M or growth >1%/day)
   - New phantom EXPIRED rows (pnl=0, exit=entry)
   - New ghost cohorts (constant-PnL clusters >100 rows)
   - PnL mismatch rate on recent closed rows (sample 500)
   - Forward validator liveness (last WON/LOST timestamp)
   - `ml_feature_store` target NULL rate
3. Outputs severity-graded alerts to dashboard

**Dashboard surfacing:** New panel on `/audit` — "DB Health" with traffic-light indicators

**Estimated impact:** Prevents data corruption from silently degrading predictions

**Effort:** 2h (prompt + script wrapper)

#### 3.3 `outcome_resolver_audit.md` — Resolution Integrity Check

**Personas:** `audit-resolver-v2`, `cross-asset-quant`

**Triggers:** After every `universal_pick_resolver.py` run

**What it does:**
1. Audits the resolver output:
   - Are CRYPTO picks resolving at 0.1bp threshold? (vs 5bp for non-crypto)
   - Are any picks stuck "OPEN" past their intended horizon?
   - Are phantom resolutions (pnl=0, exit=entry) being created?
   - Are TP/SL hits being correctly detected vs time exits?
2. Cross-checks a random sample (50 picks) against live price data
3. Reports resolver accuracy by asset class

**Dashboard surfacing:** "Resolver Health" gauge on `/audit/hyrotrader`

**Estimated impact:** Fixes the 100% phantom rate on non-crypto EXPIRED → accurate PF calculations

**Effort:** 2.5h (prompt + resolver integration)

#### 3.4 `ml_model_quality_gate.md` — ML Readiness Gate

**Personas:** `ml-validation-specialist` (already authored, never dispatched!)

**Triggers:** Before any ML model retraining cycle

**What it does:**
1. Checks `ml_feature_store` — are targets populated? (Currently ALL NULL)
2. Runs DSR (Deflated Sharpe Ratio) on any reported Sharpe
3. Runs PSR (Probabilistic Sharpe Ratio) at α=0.05
4. Computes MinTRL (Minimum Track Record Length)
5. Applies Bonferroni-Holm multiple-testing correction
6. **Rejects** any model where:
   - Targets are NULL → can't train
   - DSR < 0.5 → edge not statistically significant
   - PSR < 0.7 → insufficient probability of positive Sharpe
   - n < MinTRL → not enough data

**Dashboard surfacing:** "ML Gate" status on `/audit/hyrotrader` — green/yellow/red per model

**Estimated impact:** Prevents ML from training on garbage + surfaces statistical validity

**Effort:** 1.5h (prompt only — persona already exists, just needs dispatch)

#### 3.5 `synthetic_data_detector.md` — Fake Data Flag

**Personas:** `data-quality-auditor`, `score-methodology-auditor`

**Triggers:** Weekly

**What it does:**
1. Scans for synthetic/hardcoded data patterns:
   - Exactly +5.0% / -3.0% PnL (goldmine_cursor_predictions)
   - All trades having identical PnL per strategy (constant-PnL cohorts)
   - Strategies where `exit_price == entry_price` for 100% of closed trades
   - Confidence values that are always the same integer
2. Flags tables/strategies with synthetic data
3. Reports false performance that inflates dashboard metrics

**Dashboard surfacing:** "Data Integrity" badge — warns when synthetic data is inflating WR/PF

**Estimated impact:** Eliminates ghost rows from consensus → accurate PF

**Effort:** 1.5h

#### 3.6 `cross_asset_risk_monitor.md` — Portfolio Risk & Correlation

**Personas:** `cross-asset-analyst`, `risk-governance-officer`, `cross-asset-quant`

**Triggers:** Daily

**What it does:**
1. Reads all active OPEN picks across asset classes
2. Computes cross-asset correlation matrix (CRYPTO↔EQUITY↔FOREX↔COMMODITY)
3. Detects concentration risk:
   - >30% in single asset class
   - >15% in single strategy
   - >50% LONG in correlated assets
4. Checks drawdown vs T1/T2/T3 floors (T1<10%, T2<20%, T3<30%)
5. Flags: "Portfolio 72% CRYPTO LONG — diversification violated"

**Dashboard surfacing:** "Risk Dashboard" panel — correlation heatmap, concentration warnings

**Estimated impact:** Prevents correlated blow-ups + enforces diversification

**Effort:** 2.5h (prompt + correlation computation)

#### 3.7 `position_sizing_review.md` — Kelly & Risk Sizing Audit

**Personas:** `risk-of-ruin-assessor`, `rr-band-optimizer`, `transaction-cost-modeler`

**Triggers:** After every `elite_scorer.py` cycle

**What it does:**
1. For each active pick: computes optimal Kelly fraction
2. Flags negative-Kelly allocations (edge is negative → should not trade)
3. Enforces R:R band sweet spot (1.5-2.0R where PF=5.81, vs >2.0R where PF=0.35)
4. Models transaction costs per asset class
5. Reports net-of-cost PF (vs gross PF shown on dashboard)

**Dashboard surfacing:** "Sizing Health" — Kelly-fraction gauge, net-PF vs gross-PF delta

**Estimated impact:** +0.3 PF (eliminating negative-Kelly trades) + transparency on net-vs-gross

**Effort:** 2h

## 6. Dispatch Architecture

### Option A: GitHub Actions Cron (Recommended for initial rollout)

```yaml
# .github/workflows/swarm-prediction-health.yml
name: Swarm Prediction Health
on:
  schedule:
    - cron: '0 */6 * * *'  # Every 6 hours
  workflow_dispatch:

jobs:
  strategy-kill-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run strategy kill swarm
        run: |
          python tools/swarm/swarm_run.py \
            --prompt-file tools/swarm/prompts/strategy_kill_review.md \
            --engines deepseek,xai,cerebras \
            --max-parallel 3 \
            --out-dir swarm_runs/strategy_kill_$(date -u +%Y%m%dT%H%M%SZ) \
            --red-team
      - name: Run swarm_inspect
        run: python tools/swarm/swarm_inspect.py --latest
      - name: Commit results
        run: |
          git add swarm_runs/
          git commit -m "swarm: strategy kill review $(date -u +%Y%m%dT%H%M%SZ) [skip ci]" || true
          git push
```
