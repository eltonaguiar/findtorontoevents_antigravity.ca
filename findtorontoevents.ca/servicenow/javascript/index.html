1. Overview & Execution Contexts Foundation

ServiceNow JavaScript runs in two primary contexts: server-side (Java 8 Rhino engine) and client-side (browser). Understanding where your code executes determines which APIs are available.

Server-Side (Rhino)

  • Business Rules, Script Includes, Scheduled Jobs, UI Actions (server), REST Resources
  • APIs: GlideRecord, GlideSystem (gs), GlideDateTime, GlideAggregate, GlideAjax (server responder)
  • Global scope by default; scoped apps require explicit cross-scope grants

Client-Side (Browser)

  • Client Scripts, UI Actions (client), UI Pages, Service Portal widgets
  • APIs: g_form, g_user, g_list, g_scratchpad, GlideAjax (client caller)
  • Modern ES6+ supported in recent releases (const/let, arrow functions, template literals, destructuring)

Execution Lifecycle

User opens form → onLoad Client Script → Display BR → g_scratchpad → User changes Priority → onChange Client Script → Submit → onSubmit Client Script → Before Business Rule → Record insert/update → After Business Rule → Async Business Rule

2. GlideRecord — CRUD Patterns Server

GlideRecord is the primary server-side API for querying, inserting, updating, and deleting records. Always prefer encoded queries for complex logic and always add query conditions on large tables.

2.1 Basic Query & Iteration

Server IncidentEscalation.businessrule 
var gr = new GlideRecord('incident');
gr.addActiveQuery();
gr.addQuery('priority', 1);
gr.addQuery('sys_created_on', '>=', 'javascript:gs.daysAgoStart(7)');
gr.query();
while (gr.next()) {
    gs.info('Active P1: {0} — {1}', gr.number, gr.short_description);
}

2.2 Encoded Queries

Server MyUtils.scriptinclude 
var gr = new GlideRecord('incident');
gr.addEncodedQuery('active=true^priority=1^sys_created_on>=javascript:gs.daysAgoStart(7)');
gr.query();
while (gr.next()) { /* ... */ }

// Or pass directly to constructor
var gr2 = new GlideRecord('incident', 'active=true^priority=1');

5. GlideDateTime — Dates & Timezones Server

GlideDateTime handles timezone-aware date/time operations. Always use this instead of native JavaScript Date for server-side work.

Construction

var gdt = new GlideDateTime();                    // now (UTC)
var gdt2 = new GlideDateTime('2024-06-15 14:30:00'); // parse string
var gdt3 = new GlideDateTime(gs.nowDateTime());      // from gs helper

Display & Value

gdt.getDisplayValue();        // user timezone
gdt.getValue();               // internal (UTC) string
gdt.getNumericValue();        // epoch ms
gdt.getDisplayValueInternal();// yyyy-MM-dd HH:mm:ss
gdt.getDate();                // GlideDate portion
gdt.getTime();                // GlideTime portion

Component Getters

gdt.getDayOfMonth();          // 1-31
gdt.getDayOfWeek();           // 1=Sun ... 7=Sat
gdt.getMonth();               // 1-12
gdt.getYear();
gdt.getHours(); gdt.getMinutes(); gdt.getSeconds();

Arithmetic

gdt.addDays(5); gdt.addDaysUTC(5);
gdt.addWeeks(2); gdt.addMonths(1); gdt.addYears(1);
gdt.subtractDays(3);

Comparisons

if (gdt.after(start)) { ... }
if (gdt.before(end)) { ... }
if (gdt.equals(other)) { ... }

Parsing from Display

Common Patterns

Role-Based UI Logic

Client Incident — onLoad 
function onLoad() {
    if (g_user.hasRole('admin')) {
        g_form.setVisible('admin_only_field', true);

        g_form.setVisible('admin_only_field', false);

Security note: Client-side role checks are for UX only. A malicious user can bypass them. Always enforce authorization server-side (ACLs, Business Rules, or gs.hasRole()).

11. GlideAjax — Async Server Calls Client + Server

GlideAjax lets client-side code call a server-side Script Include asynchronously. It requires two halves: a server-side responder (extends AbstractAjaxProcessor) and a client-side caller. Both are shown below.

11.1 Server Side — Script Include (Responder)

Server MyAjaxUtils.scriptinclude 
var MyAjaxUtils = Class.create();
MyAjaxUtils.prototype = Object.extendsObject(AbstractAjaxProcessor, {

    // Called via sysparm_name = 'getCallerInfo'
    getCallerInfo: function() {
        var id = this.getParameter('sysparm_caller_id');
        if (!id) return JSON.stringify({ error: 'Missing caller_id' });

        var gr = new GlideRecord('sys_user');
        if (!gr.get(id)) return JSON.stringify({ error: 'User not found' });

        return JSON.stringify({
            name: gr.getDisplayValue('name'),
            email: gr.getValue('email'),
            vip: gr.getValue('vip') == 'true',
            manager: gr.manager.getDisplayValue()
        });
    },

    // Called via sysparm_name = 'getOpenIncidentCount'
    getOpenIncidentCount: function() {
        var callerId = this.getParameter('sysparm_caller_id');
        var agg = new GlideAggregate('incident');
        agg.addQuery('caller_id', callerId);
        agg.addActiveQuery();
        agg.addAggregate('COUNT');
        agg.query();
        var count = 0;
        if (agg.next()) count = agg.getAggregate('COUNT');
        return count.toString();
    },

    type: 'MyAjaxUtils'
});

11.2 Client Side — Caller

Client Incident — onChange — Caller 
function onChange(control, oldValue, newValue, isLoading) {
    if (isLoading || !newValue) return;

    // 1. Create the GlideAjax object with the Script Include name
    var ga = new GlideAjax('MyAjaxUtils');

    // 2. Specify which server method to call
    ga.addParam('sysparm_name', 'getCallerInfo');

    // 3. Pass parameters (prefixed with sysparm_)
    ga.addParam('sysparm_caller_id', newValue);

    // 4. Handle the async response
    ga.getXMLAnswer(function(answer) {
        var info = JSON.parse(answer);
        if (info.error) {
            g_form.showFieldMsg('caller_id', info.error, 'error');
            return;
        }
        if (info.vip) {
            g_form.addInfoMessage('VIP caller: ' + info.name);
        }
        g_form.setValue('comments', 'Manager: ' + info.manager);
    });
}

11.3 Client Side — Synchronous Variant (use sparingly)

Client Incident — onLoad (sync) 
// getXMLWait() blocks the UI thread — avoid unless absolutely necessary
var ga = new GlideAjax('MyAjaxUtils');
ga.addParam('sysparm_name', 'getOpenIncidentCount');
ga.addParam('sysparm_caller_id', g_form.getValue('caller_id'));
ga.getXMLWait();                       // blocks until response
var count = ga.getAnswer();            // read the result
g_form.setValue('u_open_count', count);
Best practice: Prefer getXMLAnswer(callback) (async) over getXMLWait() (sync). Synchronous calls freeze the browser and degrade the user experience. If you only need data at form load, use g_scratchpad from a Display Business Rule instead — it avoids the round-trip entirely.

11.4 Response Methods Deep Dive: getXMLAnswer vs getXML vs getXMLWait

GlideAjax has three primary ways to receive the server response. They differ in asynchronous vs synchronous, what the callback receives (string vs full XML), and blocking behavior.

MethodAsync?Callback receivesBest for
ga.getXMLAnswer(fn) ✅ Async String — exactly what your server method returned Most common use case. Simple values or JSON strings.
ga.getXML(fn) ✅ Async XMLDocument / response object — full envelope When you need error codes, duration, or other response metadata.
ga.getXMLWait() + ga.getAnswer() ❌ Sync (blocks UI) getAnswer() returns String Only when you truly need synchronous behavior (rare).

A. getXMLAnswer(callback) — Receives the raw return value as a STRING

The callback parameter is always a string, even if your server method returned JSON or a number. You must parse it yourself.

Client getXMLAnswer — string handling 
var ga = new GlideAjax('MyAjaxUtils');
ga.addParam('sysparm_name', 'getCallerInfo');
ga.addParam('sysparm_caller_id', g_form.getValue('caller_id'));

ga.getXMLAnswer(function(answer) {
    // 'answer' is ALWAYS a string here
    console.log(typeof answer);           // "string"

    // If server returned JSON string:
    var data = JSON.parse(answer);        // now an object
    g_form.setValue('caller_name', data.name);

    // If server returned a plain string or number-as-string:
    var count = parseInt(answer, 10);
});
Common mistake: Trying to treat the first parameter of getXMLAnswer as an object. It is always a string. Parse JSON explicitly.

B. getXML(callback) — Receives the full XML response envelope

Use this when you need more than just the answer value — for example, checking for errors, reading response duration, or accessing custom attributes the platform adds.

Client getXML — full envelope 
var ga = new GlideAjax('MyAjaxUtils');
ga.addParam('sysparm_name', 'getCallerInfo');
ga.addParam('sysparm_caller_id', g_form.getValue('caller_id'));

ga.getXML(function(response) {
    // 'response' is the XMLHttpRequest-like object
    var xml = response.responseXML;                    // XMLDocument
    var root = xml.documentElement;

    // The actual return value is in the "answer" attribute
    var answerString = root.getAttribute('answer');    // still a string!

    // You can also read other useful attributes
    var error = root.getAttribute('error');            // may be null or "true"
    var elapsed = root.getAttribute('elapsed_ms');

    if (error) {
        g_form.addErrorMessage('Server error: ' + answerString);
        return;
    }

    var data = JSON.parse(answerString);
    // use data...
});

C. getXMLWait() + getAnswer() — Synchronous (blocks the browser)

getXMLWait() pauses JavaScript execution until the server responds. After it returns, call getAnswer() to retrieve the string value.

Client getXMLWait — synchronous 
var ga = new GlideAjax('MyAjaxUtils');
ga.addParam('sysparm_name', 'getOpenIncidentCount');
ga.addParam('sysparm_caller_id', g_form.getValue('caller_id'));

ga.getXMLWait();                       // BLOCKS the UI thread until response arrives
var answerStr = ga.getAnswer();        // string — same as getXMLAnswer would give
var count = parseInt(answerStr, 10);
g_form.setValue('u_open_count', count);

Decision Guide — Which Method Should You Use?

ScenarioRecommended MethodReason
Normal form interaction, most cases getXMLAnswer(callback) Non-blocking, simple, sufficient 95% of the time.
Need to inspect error state or timing from the platform getXML(callback) Access to full response envelope attributes.
Data required before any further code can run (very rare) getXMLWait() + getAnswer() Only acceptable when you have no other choice. Freezes the browser tab.
Data needed at form load Use g_scratchpad instead No AJAX round-trip at all. Much faster and cleaner.
Never use getXMLWait in onChange or onSubmit handlers that users interact with frequently. It will make the form feel frozen.

3. Map + Set — Deduplicate Callers from Incidents

Server — Script Include 
var IncidentUtils = Class.create();
IncidentUtils.prototype = {
    getUniqueCallers: function(assignmentGroup) {
        const callerSet = new Set();
        const callerMap = new Map();

        const gr = new GlideRecord('incident');
        gr.addQuery('assignment_group', assignmentGroup);
        gr.addQuery('active', true);
        gr.query();

        while (gr.next()) {
            const callerId = gr.caller_id + '';
            if (!callerSet.has(callerId)) {
                callerSet.add(callerId);
                callerMap.set(callerId, gr.caller_id.getDisplayValue());
            }
        }
        return Array.from(callerMap.entries()); // [[sys_id, name], ...]
    },
    type: 'IncidentUtils'
};

4. Rest Parameters + Nullish Coalescing — Dynamic Query Builder

Server — Script Include 
var QueryBuilder = Class.create();
QueryBuilder.prototype = {
    buildEncodedQuery: function(...conditions) {
        // conditions: [{field: 'priority', op: '=', val: 1}, ...]
        return conditions
            .filter(c => c.field && c.val != null)
            .map(c => `${c.field}${c.op ?? '='}${c.val}`)
            .join('^');
    },
    type: 'QueryBuilder'
};

// Usage in Business Rule:
const qb = new QueryBuilder();
const query = qb.buildEncodedQuery(
    {field: 'active', val: true},
    {field: 'priority', op: '>=', val: 2},
    {field: 'assignment_group', val: current.assignment_group}
);
gr.addEncodedQuery(query);

5. Safe Property Access — Avoid NPE on Reference Fields

Server — Business Rule 
// Defensive coding: reference fields may be null
(function executeRule(current, previous) {
    'use strict';

    const manager = current.caller_id?.manager?.getDisplayValue() ?? 'No manager';
    const dept = current.caller_id?.department?.name ?? 'Unassigned';

    current.work_notes = `Manager: ${manager} | Dept: ${dept}`;

    // Safe GlideDateTime arithmetic (ES6 template + modern date handling)
    const opened = new GlideDateTime(current.opened_at);
    const now = new GlideDateTime();
    const ageHours = (now.getNumericValue() - opened.getNumericValue()) / (1000 * 60 * 60);

    if (ageHours > 24 && current.priority == 1) {
        gs.warn(`Stale P1: ${current.number} open for ${ageHours.toFixed(1)}h`);
    }
})(current, previous);
Scoped App Requirement: These examples require a custom Scoped Application with ES6+ enabled (Tokyo+). Global scope and many OOTB apps still use the Rhino ES5 engine — test thoroughly before adopting.

// Only returns records current user can read
    Important: GlideRecord bypasses ACLs by default. Use GlideRecordSecure when user-triggered.

    20. Performance Beyond Query Filters Scale

    Never query inside loops (N+1)

    // BAD: N+1 query inside loop — one GlideRecord per user
var users = new GlideRecord('sys_user');
users.addQuery('active', true);
users.setLimit(50);
users.query();
while (users.next()) {
    var inc = new GlideRecord('incident');           // ← new query every iteration
    inc.addQuery('caller_id', users.sys_id);
    inc.addQuery('active', true);
    inc.query();
    // ... process incidents for this user
}

// GOOD: Single query with IN list — collect IDs first, then one query
var userIds = [];
var users = new GlideRecord('sys_user');
users.addQuery('active', true);
users.setLimit(50);
users.query();
while (users.next()) {
    userIds.push(users.sys_id + '');
}

var inc = new GlideRecord('incident');
inc.addQuery('caller_id', 'IN', userIds.join(','));
inc.addQuery('active', true);
inc.query();
while (inc.next()) {
    // process — only one query executed
    gs.info('Active incident: ' + inc.number);
}

    UI Policy is client-side only. It runs in the browser, so it is the right tool for show/hide, read-only, and mandatory appearance — but a user can bypass it. It cannot enforce anything: never treat a UI Policy as validation or authorization. Server-side enforcement belongs to Business Rules and ACLs. Prefer a UI Policy over an equivalent Client Script whenever the logic is a plain "when field X has value Y, do Z to field W" — no code, no script clutter, and it travels with the form.

    • 26. Anti-Patterns & Common Pitfalls Warnings

    ❌ Dot-walking in loops

    while (gr.next()) {
    var name = gr.caller_id.name; // N+1 risk
}

    ✅ Use getDisplayValue or preload

    gr.addQuery('caller_id.name', 'CONTAINS', 'Smith');
while (gr.next()) {
    var name = gr.caller_id.getDisplayValue();
}

    ❌ current.update() in before BR

    // before Business Rule
current.priority = 1;
current.update(); // triggers another BR round

    ✅ Modify current directly

    // before Business Rule
current.priority = 1;
// platform persists after BR completes

    ❌ Hardcoded sys_ids

    var gid = 'a1b2c3d4e5f6...'; // breaks on clone

    ✅ System properties or stable identifiers

    var gid = gs.getProperty('x_acme.default_group');
