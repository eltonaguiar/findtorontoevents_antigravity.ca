2. Set, Map or plain object — when to use which

StructureReach for it whenKey APIWatch out for
Set✳ You need uniqueness or an O(1) membership test. Dedup, "have I seen this?", two-sum complement lookup. add · has · delete · size No indexing, no ordering guarantees beyond insertion order. size, not length.
Map✳ You want a lookup table with non-string keys, or you care about insertion order. Frequency counts, graph adjacency, memoisation keyed on a tuple. get · set · has · size · keys() Object.keys(map) is [] — entries are not own properties. Use [...map.keys()].
{} Keys are strings, you want JSON.stringify to work, and the problem is small. Still the most common choice in practice. obj[k] · Object.keys · in Keys are coerced to strings; inherits from Object.prototype, so obj['constructor'] is a function, not undefined.
Why Map beats {} for a real lookup table: keys can be any type (including a tuple stringified deliberately), there is no prototype to collide with, insertion order is guaranteed, and .size is O(1). Plain objects win on ergonomics and JSON. Both are average O(1) for get/set — the performance difference is rarely the deciding factor; the semantics are.
Two {} traps that actually fail tests:
  • Prototype collisions. count['constructor'] reads the inherited function instead of undefined, so a test input containing the literal string "constructor" corrupts your counts. Fix: const count = Object.create(null), or use a Map.
  • for...in walks inherited enumerable keys. Object.prototype's built-ins are non-enumerable so they stay hidden — until some library patches the prototype. Object.keys() or for...of are the safe forms.

3. The frequency-count idiom

The single most reusable building block in the medium tier — anagrams, group-anagrams, top-K frequent, longest consecutive sequence, substring-with-concatenation.

// Object version — the default choice
const count = {};
for (const c of s) {
    count[c] = (count[c] || 0) + 1;
}

// Alternative: Map version — when keys are not strings, or you want order
const countMap = new Map();
for (const c of s) {
    countMap.set(c, (countMap.get(c) ?? 0) + 1);
}
Why the || 0 is not optional. A missing key reads as undefined, and undefined + 1 is NaN — not 1. One NaN poisons that bucket permanently, and NaN comparisons are always false, so the bug surfaces far away from its cause. ?? (nullish coalescing) does the same job in the Map form and is slightly more precise, since it only falls back on null/undefined.

5.1 Arrays & strings — one forward pass and a lookup

Two Sum — complement lookup. The Map answers “did I already see target - nums[i]?”, collapsing the O(n²) double loop into one O(n) pass. Check before you insert, or an element pairs with itself.

function twoSum(nums, target) {
    const map = new Map();
    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        if (map.has(complement)) return [map.get(complement), i];
        map.set(nums[i], i);
    }
    return [];
}

Best Time to Buy and Sell Stock — running aggregate. Carry the best value seen before the current index (minPrice) and evaluate the candidate answer at every step. Any “best pair where i < j” question collapses to this one loop.

function maxProfit(prices) {
    let minPrice = Infinity, maxProfit = 0;
    for (const price of prices) {
        minPrice = Math.min(minPrice, price);
        maxProfit = Math.max(maxProfit, price - minPrice);
    }
    return maxProfit;
}

Longest Substring Without Repeating Characters — shrink-until-valid window. Keep the invariant “[left, right] holds no repeats”: advance right, then shrink left with a while, not an if, until the window is valid again — one bad character can evict more than one occupant.

function lengthOfLongestSubstring(s) {
    const set = new Set();
    let left = 0, max = 0;
    for (let right = 0; right < s.length; right++) {
        while (set.has(s[right])) {
            set.delete(s[left]);
            left++;
        }
        set.add(s[right]);
        max = Math.max(max, right - left + 1);
    }
    return max;
}

3Sum — sort, fix one index, two-pointer the rest. Sorting turns “any triple summing to 0” into a monotone walk: sum too small → left++, too big → right--. Uniqueness needs duplicate-skipping at all three positions, not just the fixed one.

function threeSum(nums) {
    nums.sort((a, b) => a - b);
    const res = [];
    for (let i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] === nums[i - 1]) continue;
        let left = i + 1, right = nums.length - 1;
        while (left < right) {
            const sum = nums[i] + nums[left] + nums[right];
            if (sum === 0) {
                res.push([nums[i], nums[left], nums[right]]);
                while (left < right && nums[left] === nums[left + 1]) left++;
                while (left < right && nums[right] === nums[right - 1]) right--;
                left++;
                right--;
            } else if (sum < 0) left++;
            else right--;
        }
    }
    return res;
}
Transferable bits (arrays): the “have I seen x?” lookup is one idea wearing three costumes — Two Sum's Map, the window's Set, 3Sum's skip-past-duplicates line while (l < r && nums[l] === nums[l + 1]) l++; (copy-paste for 4Sum, 3Sum Closest, any unique-tuples ask). And when the answer is “best pair i < j”, always try a running Math.min/Math.max before reaching for a heap.

5.2 Trees — the same four lines, every time

Invert Binary Tree — the recursion template. Guard on null, recurse both children, combine. The destructuring swap does the mirroring in one line✳, and the right subtree is evaluated before the left is touched.

function invertTree(root) {
    if (!root) return null;
    [root.left, root.right] = [invertTree(root.right), invertTree(root.left)];
    return root;
}

Validate Binary Search Tree — carry the invariant down. Same skeleton, but each call threads a (min, max) range: the left child inherits an upper bound of node.val, the right child a lower bound. Comparing each node to its immediate parent only is the classic wrong answer.

function isValidBST(root) {
    function validate(node, min, max) {
        if (!node) return true;
        if (node.val <= min || node.val >= max) return false;
        return validate(node.left, min, node.val) && validate(node.right, node.val, max);
    }
    return validate(root, -Infinity, Infinity);
}
Transferable bits (trees): guard on null → recurse left → recurse right → combine is the whole of max depth, diameter, level order and path sums. The Validate-BST upgrade — thread state through the recursion instead of reading it from the parent — is how you also solve symmetric tree, count-good-nodes and burn-the-tree problems.

5.3 Graphs — mark visited, detect the back edge

Number of Islands — flood fill. Walk every cell; on an unvisited '1', increment the count and DFS to sink the whole component so it can never be counted twice. The input grid is the visited set.

function numIslands(grid) {
    if (!grid.length) return 0;
    const rows = grid.length, cols = grid[0].length;
    let count = 0;

    function dfs(r, c) {
        if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] === '0') return;
        grid[r][c] = '0';
        dfs(r + 1, c); dfs(r - 1, c); dfs(r, c + 1); dfs(r, c - 1);
    }

    for (let r = 0; r < rows; r++) {
        for (let c = 0; c < cols; c++) {
            if (grid[r][c] === '1') {
                count++;
                dfs(r, c);
            }
        }
    }
    return count;
}

Course Schedule — 3-colour DFS cycle detection. 0 unvisited, 1 visiting (on the current path), 2 finished. Hitting a 1 means a back edge — a dependency cycle — and no ordering exists.

function canFinish(numCourses, prerequisites) {
    const graph = Array.from({ length: numCourses }, () => []);
    for (const [course, pre] of prerequisites) graph[pre].push(course);

    const visited = new Array(numCourses).fill(0); // 0 = unvisited, 1 = visiting, 2 = visited

    function hasCycle(node) {
        if (visited[node] === 1) return true;
        if (visited[node] === 2) return false;
        visited[node] = 1;
        for (const neighbor of graph[node]) {
            if (hasCycle(neighbor)) return true;
        }
        visited[node] = 2;
        return false;
    }

    for (let i = 0; i < numCourses; i++) {
        if (hasCycle(i)) return false;
    }
    return true;
}
Transferable bits (graphs): “visited by mutation” (grid[r][c] = '0') is the same idea as a seen Set — Rotting Oranges, Max Area of Island, Surrounded Regions. And the 0/1/2 colour array is the generic “does a valid order exist?” tool: push each node after its neighbours recurse and you get Course Schedule II's order; add recursion-depth tracking and you have the cycle to report in Alien Dictionary.

5.4 Design — one O(1) trick instead of a linked list

LRU Cache — Map insertion order is recency order. Reading a key and re-inserting it moves it to the most-recent end; evicting the least recent is deleting the first key from map.keys(). Both operations are O(1).

class LRUCache {
    constructor(capacity) {
        this.capacity = capacity;
        this.map = new Map();
    }

    get(key) {
        if (!this.map.has(key)) return -1;
        const value = this.map.get(key);
        this.map.delete(key);
        this.map.set(key, value); // move to end (most recent)
        return value;
    }

    put(key, value) {
        if (this.map.has(key)) this.map.delete(key);
        this.map.set(key, value);
        if (this.map.size > this.capacity) {
            const oldest = this.map.keys().next().value;
            this.map.delete(oldest);
        }
    }
}
Transferable bits (design): JS Map and Set iterate in insertion order✳, so delete+re-insert means “move to most recent” and keys().next().value means “oldest” — say that sentence in the interview, because in a language without ordered maps you would be handed a hash map plus a hand-rolled doubly linked list. The same property gives you a size-bounded cache in three lines.

5.5 Dynamic programming — ask what dp[i] depends on

House Robber — rolling variables. dp[i] depends only on the two cells before it, so the array is dead weight: prev2 is dp[i-2], prev1 is dp[i-1], both shift right each step.

function rob(nums) {
    let prev2 = 0, prev1 = 0;
    for (const num of nums) {
        const curr = Math.max(prev1, prev2 + num);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}

Coin Change — bottom-up table with an impossible sentinel. dp[i] = fewest coins to reach amount i, seeded with Infinity except dp[0] = 0; each cell takes the min over “use one coin of this size”.

function coinChange(coins, amount) {
    const dp = new Array(amount + 1).fill(Infinity);
    dp[0] = 0;
    for (let i = 1; i <= amount; i++) {
        for (const coin of coins) {
            if (i - coin >= 0) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    return dp[amount] === Infinity ? -1 : dp[amount];
}
Transferable bits (DP): ask “what does dp[i] depend on?” Two previous cells → two variables (House Robber, Climbing Stairs, Min Cost Climbing Stairs). A range of smaller answers → a table (Coin Change, Perfect Squares, Word Break). Initialise unreachable cells with Infinity, keep dp[0] as the empty-case identity (0 coins, 0 ways), and translate the sentinel into the problem's failure value (-1) once, after the loop — never inside it.
How to use section 5 in a real interview: name the concept out loud before you code — “frequency map”, “shrink-until-valid window”, “3-colour DFS”, “rolling variables”. It tells the interviewer where you are going, and — more importantly — it stops you re-deriving a known solution from scratch under pressure. The specific problem is just the concept in costume.
