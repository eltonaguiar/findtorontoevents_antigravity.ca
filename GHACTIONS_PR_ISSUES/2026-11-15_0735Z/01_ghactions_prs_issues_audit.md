### 1.3 Actions to Fix

#### Priority 1: Critical Data Freshness Failures

**Issue A: `dashboard_data.json` missing in Backup Restore Verification**

- **Root Cause:** The `audit_dashboard/data/dashboard_data.json` file is either:
  1. Not being committed to `main` (e.g., excluded by `.gitignore`, removed by a previous commit, or never generated by `audit-dashboard.yml`).
  2. Being deleted by a subsequent workflow step before the backup-verify job runs.
  3. Being generated in a separate branch (e.g., `gh-pages` or a feature branch) instead of `main`.

- **Fix Required:**
  1. Verify `.gitignore` does not exclude `audit_dashboard/data/dashboard_data.json`:
     ```bash
     grep -n "dashboard_data.json" .gitignore
     ```
  2. Ensure `audit-dashboard.yml` is running and committing the file:
     ```bash
     gh run list --workflow=audit-dashboard.yml --limit 3
     ```
  3. If the file is generated by `audit-dashboard.yml`, verify that the "Deploy to GitHub Pages" or "Commit and Push" step is not failing silently.
  4. If the file is intentionally not on `main` (e.g., built artifact), adjust `backup-verify.yml` to download it from the `gh-pages` branch or from the latest `audit-dashboard.yml` run artifact.

**Immediate Action:** Inspect the latest `audit-dashboard.yml` run and its artifacts. If missing, re-trigger it manually:
```bash
gh workflow run audit-dashboard.yml --ref main
```

**Issue B: QA Market Validation — Missing Quote Chain Credentials**

- **Root Cause:** `.github/workflows/qa-market-validation.yml` does not pass `FINNHUB_API_KEY`, `TIINGO_API_KEY`, `TWELVE_DATA_API_KEY`, `ALPHA_VANTAGE_API_KEY`, or `FMP_API_KEY` into the `Run QA ledger` step. The `alpha_engine/equity_price_failover.py` module expects these env vars to activate its 7-adapter failover chain. Without them, only Stooq (blocked from GHA runner IPs) and yfinance (flaky in GHA) are active, causing all equity tickers to fail.

- **Fix Required:**
  Edit `.github/workflows/qa-market-validation.yml` to add the following to the `Run QA ledger` step's `env`:
  ```yaml
  FINNHUB_API_KEY: ${{ secrets.FINNHUB_API_KEY || secrets.FINNHUB }}
  FINNHUB: ${{ secrets.FINNHUB_API_KEY || secrets.FINNHUB }}
  TIINGO_API_KEY: ${{ secrets.TIINGO_API_KEY }}
  TWELVE_DATA_API_KEY: ${{ secrets.TWELVE_DATA_API_KEY }}
  ALPHA_VANTAGE_API_KEY: ${{ secrets.ALPHA_VANTAGE_API_KEY }}
  FMP_API_KEY: ${{ secrets.FMP_API_KEY }}
  ```
  **Note:** The repo currently has `FINNHUB_API_KEY` and `FINNHUB` configured as secrets, but `TIINGO_API_KEY` and `TWELVE_DATA_API_KEY` are missing. Adding the missing secrets will increase the failover chain from 5/7 to 7/7.

**Issue C: RSI 5-70 Forward-Test Snapshot & Operator Review — Push Retry Without Rebase**

- **Root Cause:** Both workflows use a retry loop for `git push origin HEAD:main`, but on a `non-fast-forward` rejection, they do not rebase onto the latest `origin/main`. Every subsequent attempt sends the same ref update, which can never succeed.

- **Fix Required:**
  Update the push retry logic in both `.github/workflows/rsi5070-forward-snapshot.yml` and `.github/workflows/operator-review-today.yml` to include a rebase step on rejection:
  ```bash
  if echo "$push_output" | grep -qiE "non-fast-forward|fetch first|\[rejected\]|behind its remote"; then
    if git fetch --quiet origin main && git rebase --quiet origin/main; then
      echo "Rebased onto origin/main — retrying push immediately"
      continue
    fi
    git rebase --abort >/dev/null 2>&1 || true
    echo "::warning::rebase onto origin/main failed — falling back to timed retry"
  fi
  ```
  This pattern is already documented in the `operator-review-today.yml` and `rsi5070-forward-snapshot.yml` workflows (PR #786).

**Issue D: Sports Smoke — Runner Image Drift**

- **Root Cause:** `ubuntu-latest` resolves to Ubuntu 26.04, which Playwright 1.58.2 does not officially support. The install step fails with `ERROR: Playwright does not support chromium on ubuntu26.04-x64`.

- **Fix Required:**
  Pin the `smoke` job in `.github/workflows/sports-smoke-and-e2e.yml` to `ubuntu-24.04`:
  ```yaml
  runs-on: ${{ vars.ACTIONS_RUNNER_LABEL || 'ubuntu-24.04' }}
  ```
  This is documented in PR #786.
