You are a hedge fund quant architect evaluating a Persona-Based Safe-Pick system for asset-class recommendations.

## Context

Our project (findtorontoevents.ca/audit) tries to predict stocks/crypto/forex/bonds/commodities/futures/ETFs. We have:
- A per_asset_class_predictor with verified IC weights
- A conviction_stack with S/A/B tiers
- hedge_fund_quality_gate with per-class rejection rules
- An EDGE_CRITERIA_ACTION_PLAN showing 6 actionable gaps
- Only 2 proven edge pairs: deep_value×EQUITY (n=60, WR 60.0%) and momentum_breakout×ETF (n=46, WR 58.7%)

## The Proposal: Persona-Based Safe-Pick LLM System

A prompt template that defines "personas" per asset class, each with:
1. Persona Name & Role
2. Core definition of "safe" (volatility, drawdown, credit quality, liquidity, yield)
3. Data sources & frequency
4. Algorithmic filters (step-by-step rules)
5. Back-testing protocol (Sharpe, max DD, CAGR thresholds)
6. JSON output format

Plus a Python script that screens stocks/ETFs/crypto using yfinance with thresholds:
- Stocks: market_cap>$50B, vol<12%, beta<0.9, D/E<0.4, FCF growth>5%, div_yield≥1%, Sharpe>1.2, max DD<12%, CAGR>8%
- Crypto: vol<30% (very generous)
- Composite safety score (0-1) normalized from above metrics
