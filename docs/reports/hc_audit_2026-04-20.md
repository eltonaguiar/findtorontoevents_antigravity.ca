## 2. Fixes Applied

### 2.1 Trust threshold alignment (`audit_dashboard/template.html`)

**Problem:** `hcEdgeManifest()` and `passesValidatedEdgePerClass()` hardcoded `trust >= 3` for CRYPTO and EQUITY, but the actual shared gates in `hc_filter.js` enforce `trustScoreMinCrypto: 6` / `trustScoreMinOther: 5`.

**Impact:** Users read "Trust ≥ 3" in the explainer panel, but picks with trust 3–5 are silently rejected by `passesHighConvictionPick`. The UX is misleading.

**Fix:**
- `hcEdgeManifest()`: drives trust display from `getHcGateParams()` (`trustScoreMinCrypto` / `trustScoreMinOther`).
- `passesValidatedEdgePerClass()`: computes `trustFloor` dynamically from same config source.
- FOREX row also shows trust floor for parity.

### 2.2 Config completeness (`config/hc_gate_params.json`)

**Problem:** The JSON config only had generic `forwardWRMinPct` and `scoreCompoundFloor`. It was missing per-asset keys that `hc_filter.js` and `dashboard_hc_rules.py` reference:
- `forwardWRMinPct{Commodity,Futures,Bond,ETF}`
- `scoreFloor{Commodity,Futures,Bond,ETF}`
- `forexRelaxedWRMinPct`

**Impact:** Operators editing only the JSON file might think they tuned crypto FWD when they did not; the JS/Python embedded defaults masked the gap.

**Fix:** Added all missing per-asset tunables to `hc_gate_params.json` with values matching the embedded defaults.

### 2.3 Python/JS parity (`tools/dashboard_hc_rules.py`)

**Problem:** `hc_filter.js` retired `ai_challenge_antigravity`, `ai_challenge_grok`, `ai_challenge_mercury` on 2026-04-18 (LLM tournament ended), replacing them with `ai_challenge_predictable` and `ai_challenge_scanner`. Python `_EMBEDDED_DEFAULTS` still listed the retired entries.

**Fix:** Updated `dashboard_hc_rules.py` `ai_challenge` signal group to match JS.

### 2.4 Score bucket naming (`audit_dashboard/template.html`)

**Problem:** `_cryptoScoreBucket()` labeled score thresholds (70+/55–70/40–55/<40) as "S-Tier", "A-Tier", etc. This conflates `p.score` bands with stamped **HF conviction tiers** (S/A/B from `conviction_stack`), inviting false conclusions.

**Fix:** Renamed to "Score band S (70+)", "Score band A (55–70)", etc.

### 2.5 PF cap (`audit_dashboard/template.html`)

**Problem:** When a small slice had zero losses, PF computed as `999` and displayed as `∞`.

**Fix:** Cap at `99.9`; display "n/a (no losses)" when `grossLosses === 0`.

### 2.6 Non-crypto aggregate Recent-N (`audit_dashboard/template.html`)

**Problem:** Per-category cards applied `_applyRecentN`, but the top aggregate header always used the full history (or killed-excluded full history), causing identical aggregate numbers across Last 10 vs Last 50.

**Fix:** Aggregate now recomputes from `_applyRecentN(closedPicks, _PERF_RECENT_N)` when Recent-N is active.

## 4. Recommendations

1. **Do not rely on HC preset for crypto until input gaps are fixed.**
   - 15.8% of active picks lack `strat_fwd_wr`; this alone blocks HC.
   - The train/test overfit (71% → 32% WR) means the current thresholds were calibrated on a regime that no longer holds.

2. **Add `strat_fwd_wr` backfill for active picks.**
   - If a strategy has closed-book history, project its forward WR onto active picks so they are not penalized for missing data.

3. **Consider lowering crypto score floor temporarily.**
   - Current `scoreFloorCrypto: 55` + `trustScoreMinCrypto: 6` produces only 8.8% HC pass rate on active picks.
   - Recent crypto baseline is 90% WR (last 10) — the floor may be filtering out edge rather than noise.

4. **Run `validate_dashboard_parity.py` on every HC-related PR.**
   - The JS/Python drift on `ai_challenge` signals went unnoticed until this audit.

5. **Relabel crypto "Realized PnL" to "Σ pnl_pct (capped/trade)" with mean/median prominently shown.**
   - Already partially addressed by tooltips; consider elevating mean to the card header.
