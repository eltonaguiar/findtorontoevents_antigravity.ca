## PART 0 — Strategy before the list

### The anti-goal

A 100-item list is a temptation to generate 100 more backtests. **That would be self-defeating and I am refusing it.** Measured this session: 146 pre-registered hypotheses, 0/55 survive deflation, and one additional trial at N=147 widens the deflation penalty on *everything already measured*. A programme that responds to "0 proven edges" by running 100 more tests does not get 100 chances — it gets a worse threshold and the same zero.

So the 100 items are partitioned by what they buy:

| Bucket | What it buys | Item budget |
|---|---|---|
| **A. Measurement integrity** | a single cost of record, so a kill means something | 12 |
| **B. Data provenance (PIT)** | the right to believe a fundamental test once, not nine times | 10 |
| **C. Trial-debt management** | the only lever that raises the deflation threshold | 10 |
| **D. Gate infrastructure** | the machinery that decides alive/dead, incl. the missing β-hurdle | 14 |
| **E. Per-class honest verdicts** | measured DEAD or measured ALIVE, no maybes | 12 |
| **F. Live-surface truthfulness** | `/audit` must not show numbers we'd disown | 10 |
| **G. CI / provenance plumbing** | a claim that cannot silently skip is worth trusting | 10 |
| **H. Fleet/peer obligations** | assigned reviews, corrections, handoffs | 8 |
| **I. Registers, memory, docs** | so the next session doesn't redo this | 8 |
| **J. Guardrails (do-NOT)** | prevents the 100 items becoming damage | 6 |

### The three rules this list obeys

1. **A measurement is worth more than a test.** Items that make a *future* test credible outrank items that run another test.
2. **Every item has a done-condition that is a command or a byte count**, not an opinion. "Improve costs" is not an item; "round trip reproducible to ±0.5bp from a committed artifact" is.
3. **Blocked items are labelled BLOCKED with the blocker named**, because a backlog that hides blockers is a wish list wearing a lab coat.

### Execution order (highest value per unit of risk first)

A → D(bootstrap harness) → B(finish scale) → C → G(T3) → E → F → H → I.
Rationale: cost-of-record and the β-hurdle gate change what every *other* verdict means, so doing them first re-prices work already done. E and F come after because a verdict computed on an unreconciled cost is provisional.

### Honest capacity statement

I cannot credibly complete 100 items in one session, and claiming I did would be the exact fabrication failure this repo has documented (`docs/AGENT_DIFF_FABRICATION_PATTERN_2026-05-31.md`). What follows is the full backlog with honest status, and a committed execution log of the subset actually finished — sha per block.
